# K6.1 brief: core renderer skeleton and 'volume' lighting (T3)

Self-contained brief. Read first: [CLAUDE.md](../../../CLAUDE.md) (rules and **Traps**), the design
[K6-core-renderer.md](./K6-core-renderer.md) (§1 limits table, §2 API, §3.1–§3.4, §4, §5, §7), DECISIONS D8, D10,
D20, D21, D32 and D34 (§10 of the design until the lead copies it). Background: the TSL files you replace are
`packages/vdb/src/three/frame/{inject-material,temporal-material,integrate-material,chunks,view,layout}.ts`; the
core compute precedent is `packages/vdb/src/core/compute/{pyramid,shared}.ts`; the dense source is
`packages/vdb/src/core/source/{dense,types}.ts`; the twins are in `packages/vdb/src/tools/frame/index.ts` and
`grid.ts` (`vdbFrameReproject`).

## Goal

The core renders mjurczyk's 'volume' lighting from a dense source with no engine: compute kernels on 3D textures
(gather → resolve), a core composite pass and the WGSL function `vdbFrameIntegrate`, on the host's device and
encoder. `./three` can switch a `VDBFrameRenderer` to it with an internal `backend: 'core'` for the A/B against the
TSL path. Correctness and quality gates only; record no timings as evidence (§5.4 of the design).

## Scope (the API slice)

In: renderer skeleton (options, `VDBFrameSettings`, `addVolume`, `update`, `render`, `prepare`, `dispose`), the
retire queue, the per-device pipeline cache, uniform packers generated from field lists, froxel layout and view
maths, 'volume' lighting with: ambient + probe SH, hemisphere lights, directional / point / spot lights, HG and
dual-lobe phase (volume overrides, V65), multiple scattering `false` and `true` (1D diffusion; `'neural'` runs as
`true` in 'volume' lighting, as today), `mipmaps`, `jitter`, `fadeRadius`, `temporal`, `srgbBlending`, the `lights`
bitmask, `froxelMix: 'mixture' | 'over'`, single and multi source groups. Dense source only.

Out (later steps; keep hooks, don't build): environment terms ('outward', environment lights; K6.2), 'frame'
lighting (K6.2), octaves / two-sided / Lorenz-Mie / multi-scale / MLP (K6.3), spectral (K6.4: but size the uniform
structs and texture roles so spectral adds a second prefix without a layout change), shadows and emission (K6.5,
K6.5b), sparse source (K6.7, in parallel), level sets and points (K6.6), public exports (K6.8).

## Files

Create (core; engine-free, no `three` import; `test/boundaries.test.ts` must stay green):
- `packages/vdb/src/core/frame/renderer.ts`: `vdbCreateFrameRenderer(device, options)` → `VDBFrameRendererGpu`,
  `VDBFrameVolumeGpu`. `update()` order: collect visible volumes, clip, area, union area with last frame, group by
  source object, pack uniforms (`queue.writeBuffer`), rebuild bind groups whose inputs changed, record
  `froxelGather` per group then `froxelResolve`. `render()` records the composite render pass.
- `packages/vdb/src/core/frame/settings.ts`: `VDBFrameSettings` (his field names and v0.26 defaults, as
  `three/frame/renderer.ts` `VDBFrameRendererSettings` L100–200 and L396–431) + `froxelMix` (default `'mixture'`).
  One declaration: `./three` keeps its own type until K6.8; a unit test asserts the shared fields and defaults match.
- `packages/vdb/src/core/frame/types.ts`: `VDBFrameInput`, `VDBFrameCamera`, `VDBFrameLight`, `VDBFrameVolumeParams`,
  `VDBFrameTargets`, `VDBFrameOutputs`, `VDBFrameUpdate`, `VDBVolumeSlot` (design §2.1–§2.5; environment, occluders
  and shadow requests are typed but ignored with a one-time warning).
- `packages/vdb/src/core/frame/resources.ts`: texture allocation (3D rgba16float `STORAGE_BINDING |
  TEXTURE_BINDING`, packed `r32uint` partials allocated only for multi-group frames), the retire queue (destroy two
  updates later; `dispose()` drains), `outputs.version`.
- `packages/vdb/src/core/frame/pipelines.ts`: per-device `WeakMap` cache keyed by hash(text) + layout + formats;
  every creation inside `pushErrorScope('validation')`; `prepare()` uses `createComputePipelineAsync` /
  `createRenderPipelineAsync`. Groups 0–2 with no gaps (Traps).
- `packages/vdb/src/core/frame/uniforms.ts`: one field list per struct (`VdbFrameUniforms`, `VdbFrameLights`,
  `VdbFrameVolume` (512 B), `VdbFrameGroup` (dynamic offset, 256 B stride)) generating both the WGSL struct text and
  the TS packer.
- `packages/vdb/src/core/frame/wgsl/chunks.ts`: `frameChunksWgsl(roots)`: the `vdbFrame*` closure in fixed order
  (froxel and slice maths, noise, distance fade, box steps and lod, phase HG/dual-lobe, shadow step/depth/
  transmittance, isotropic diffusion, the light loop). Port from `three/frame/chunks.ts`; the twins already exist.
- `packages/vdb/src/core/frame/wgsl/gather.ts`: kernel `vdbFrameGatherCs`, `@workgroup_size(8, 8, 1)`, dispatch
  ⌈areaBox.w / 8⌉ × ⌈areaBox.h / 8⌉ × D over the union bounding box. Per froxel: zero if outside this frame's area;
  loop the group's volumes (rect + slice early-out from the record, box segment, his sub-step pre-integration, the
  visible position, the light loop, radiance). Combine with `'mixture'` (Σ τᵢ, Σ τᵢ·Lᵢ; design §3.4) or `'over'`
  (in record order). The shadow march is **one** function `vdbFrameShadowMarch` called from one loop (two
  `vdbSrcDensity` call sites per entry; see the level-set compile trap). Non-last groups accumulate into the packed
  partials (`pack2x16float` pairs, `r32uint` read-write); the last group reads them and writes
  `scatter` (rgba16float, write-only: premultiplied rgb, α). Noise: his formula on the virtual atlas coordinate
  (`tile·grid + xy + 0.5` with his `getAtlasLayout` columns) so parity is not lost to jitter.
- `packages/vdb/src/core/frame/wgsl/resolve.ts`: kernel `vdbFrameResolveCs`, `@workgroup_size(8, 8, 1)` over (x, y)
  columns of the union box. Per column, z = 0..D−1: with `temporal`, his reprojection (`temporal-material.ts`:
  previous view/projection/range, motion-weighted blend, 6-neighbour clamp: x±1, y±1 by `textureLoad`, z±1 from the
  column) sampling the previous history with hardware trilinear, writing history'; then his integrate step: skip once
  T < 0.001, accumulate radiance and optical depth τ = −log(1 − α), write prefix boundary z + 1. Boundary 0 = 0.
  Outside this frame's area write zeros. Prefix: rgba16float `W × H × (D + 1)`: (L rgb, τ).
- `packages/vdb/src/core/frame/wgsl/integrate.ts`: `vdbFrameIntegrateWgsl({ spectral })` →
  `fn vdbFrameIntegrate(screenUv: vec2f, sceneViewDepth: f32) -> VdbFrameIntegrated` (two taps at boundaries k and
  k + 1, design §3.4 formula, his `sliceAlpha` coverage) and `fn vdbFrameComposite(i, sceneColor, srgbBlending)`
  (his sRGB blend and clamp rules, `integrate-material.ts` L95–110, L232–251), plus `vdbFrameIntegrateEntries(slot)`.
  The core composite pass (fullscreen triangle, scissor to the froxel screen rect, depth as `texture_depth_2d` or
  `r32float`, reversed/orthographic view-Z) uses the same function.
- `packages/vdb/src/core/frame/index.ts` and additions to `packages/vdb/src/core/internal.ts` only (no
  `core/index.ts` export in K6.1; `api-surface` snapshots must not change).

Create (tools; twins, engine-free, no `core` import):
- `packages/vdb/src/tools/frame/view.ts`: plain-array ports of `three/frame/view.ts` (frustum clip of the unit box,
  clipped view depths, `getFroxelSlice`, `getFroxelSliceRange`, `getFroxelRect`, `getFroxelArea`, union of two
  areas) and of `three/frame/layout.ts` `getFroxelSize` taking `{ drawingBuffer, canvas }` instead of a renderer.
  The core imports these.
- Twins in `packages/vdb/src/tools/frame/index.ts` (or a new `froxel.ts`), exported through `tools/internal.ts`:
  `vdbFrameGatherFroxel(volumes, mode)` (mixture and over of per-volume `vdbFrameInjectSlice` results),
  `vdbFrameTemporalFroxel` (blend + clamp around `vdbFrameReproject`), `vdbFrameScanColumn(froxels, range, depth)`
  (the prefix with the T < 0.001 stop), `vdbFrameIntegratePrefix(a, b, c)` (the two-tap formula). Each gets a
  fail-before mutation in its probe.

Touch (three; internal A/B only):
- `packages/vdb/src/three/frame/renderer.ts`: an internal field `backend: 'tsl' | 'core'` (default `'tsl'`, not in
  `VDBFrameRendererSettings`, marked `@internal`). With `'core'` and `lighting: 'volume'`, the first proxy's
  `onBeforeRender` builds `VDBFrameInput` from three's camera and lights, makes a core dense source from the three
  source's `volume` (`vdbDenseSource(device, source.volume)`, cached per source), records `update()` into its own
  encoder on `getDevice(renderer)` and submits. `'core'` with `'frame'` lighting or a sparse source throws
  `VDB_BAD_OPTION` naming K6.2 / K6.7.
- `packages/vdb/src/three/frame/core-textures.ts` (new): binds a core `GPUTexture` into a stand-in
  `Data3DTexture` by setting three's backend record (`backend.get(texture).texture`) before three first uses it,
  re-set when `outputs.version` moves, with `backend.destroyTexture` guarded and a once-per-backend self-test that
  throws `VDB_ENGINE_MISMATCH` (model: `three/grid-node.ts` L138–260 for buffers).
- `packages/vdb/src/three/frame/core-integrate-material.ts` (new): the proxy material for `'core'`: a
  `NodeMaterial` whose fragment calls `wgslFn(vdbFrameIntegrateWgsl())` on the stand-in prefix texture, three's
  `viewportDepthTexture` and `viewportTexture`. Swapped onto the proxies when `backend` is `'core'`.
- `examples/src/harness/k3-frame.ts`: `?backend=core` sets the internal field.

Create (harness, specs, tests):
- `examples/src/harness/k6-core.{html,ts}`: raw WebGPU, no three, imports core and tools by path
  (`../../../packages/vdb/src/{core,tools}/internal.js`). Modes: `?probe=gather|resolve|integrate|view` runs one
  kernel on a seeded synthetic dense volume and compares ≥ 512 texels to the twin; `?scene=<K3 Step 1 name>`
  renders the scene through `update()` + `render()` into a readback target (no canvas: SwiftShader trap) and
  returns RGBA; `?mutate=<twin term>` flips one term for the fail-before checks; `?swap=1` counts
  `create*Pipeline*` / `createShaderModule` calls across a second identical frame (must be 0).
- `e2e/k6-core.spec.ts`: probes (≤ 2 f16 ulp, or a bound justified in the handoff), each probe's mutation fails, no
  validation errors (`collectErrors` from `e2e/console-errors.ts`), deterministic across two loads, zero builds on
  the second frame, the A/B below.
- `packages/vdb/test/core/frame/*.test.ts`: uniform packer offsets vs the generated WGSL structs; composed WGSL has no
  reserved words (`active`, `set`, `filter`, `target`), duplicate symbols or back-ticks (reuse
  `test/core/wgsl-names.ts`); a limits test building every K6.1 pipeline descriptor against the §1 table (≤ 2 storage
  textures, ≤ 12 sampled, ≤ 1 storage buffer, groups without gaps, 64 invocations); the retire queue on
  `test/core/fake-gpu.ts`; `tools/frame/view.ts` against `three/frame/view.ts` on random cameras and boxes; settings
  defaults equal three's.
- `packages/vdb/src/core/frame/size-snapshot.json` + its test (D21; caps in design §5.3).

## Gates (all must hold)

1. Twins: every probe within 2 f16 ulp on ≥ 99.9 % of texels; the rest explained; every mutation fails.
2. Frames vs TSL: the K3 Step 1 scenes (`step1-lighting-volume`, `step1-lights-directional`,
   `step1-multiple-scattering-off`, `step1-volume-dir-ms-off(-isolated)`, `step1-volume-dir-ms-on(-isolated)`) render
   through `?backend=core` with PSNR ≥ 45 dB and ≤ 0.2 % pixels > 4/255 against `?backend=tsl` on the same device,
   with `froxelMix` both `'mixture'` and `'over'` (single-volume scenes: identical modes).
3. Frames vs his captures: `pnpm k3:parity` Step 1 through `backend: 'core'` meets his strict bar (PSNR ≥ 40 dB,
   ≤ 0.5 % pixels > 8/255). Write a regression report (both backends' numbers per scene) into the handoff.
4. Structural: zero pipeline builds on a repeated frame; no validation errors; boundaries and api-surface unchanged;
   the TSL path's own specs unchanged.
