## K4.6: collapse uniform regions into tiles

### What it does

`tree.ts` gains a collapse pass in `assembleTree`. It runs after the leaves and input tiles are placed and before
ordering and stats. It follows OpenVDB `tools::prune(tree, tolerance = 0)` (`TolerancePruneOp`), bottom-up:

| Node | Collapses when (OpenVDB `isConstant` at tolerance 0) | Becomes |
|---|---|---|
| leaf | all 512 voxels have the same active state, and every value `=== values[0]` | lower tile (value, state) |
| lower node | no child leaf; all 4096 slots have one state and one value | upper tile |
| upper node | no child; all 32768 slots have one state and one value | root tile |

The rules:

- `===` comparison, so `-0` equals `0` and `NaN` never collapses. The tile takes the first value.
- An inactive result equal to the background is the default slot, so it is not stored.
- An upper node that collapses to an inactive background tile is removed from the root
  (`RootNode::eraseBackgroundTiles`).
- Vec3f compares per component.

Counts and stats after a collapse:

- `tileCounts`, `mVoxelCount` and the active voxel count are kept right. A collapsed leaf adds 512 tile voxels; a
  lower node that becomes an upper tile removes its 4096 lower tiles.
- min, max, the bbox and the voxel count do not change.
- Upper and root ave/stddev change. GridStats weighs a tile by its child's *slot* count (512, 4096, 32768), so a
  region weighs less once it is a tile, exactly as in a native image of the pruned tree. Do not compare ave/stddev
  across collapse on and off.

### Defaults, and why

| Entry point | `collapse` default | Why |
|---|---|---|
| `buildFromDense` | **on** | A new build with no source topology to keep. A uniform block costs one tile instead of leaves. |
| `resampleGrid` (and so `bakeCoarseFirst` previews) | **on** | Also a new build. Applied before `quantize`, which keeps tiles. |
| `buildFromLeavesDetailed` | off | The low-level re-encoding path that the two rows below use. |
| `buildFromVdb` | off | `nanovdb_convert` (CreateNanoGrid) copies the OpenVDB tree without pruning, so off keeps our image of a `.vdb` on native's topology. OpenVDB writers prune anyway (0 gain measured below). |
| `quantize(…, tol, { collapse })` | off | Re-encoding a native FLOAT image must keep native's node counts and Fp8 sizes (K4.1 parity). Without the option, output is byte-identical to before. |
| `bakeCoarseFirst({ collapse })` | previews on, full grid off | A value passed applies to every grid. |
| `collapseGrid(image)` (new) | always | Re-encodes a FLOAT image with collapse on. |

What the numbers say:

- **Real inputs gain nothing on re-encode.** The native primitives already hold their uniform interiors as tiles
  (that was the K4.1 fix of the old "~12% Fp8 gap"). The openvdb.org `.vdb` files are already pruned, and their
  leaves are not uniform anyway.
- **The win is in our own builds of uniform interiors.** Dense builds with saturated cores, and resamples of
  WDAS's tiled interior at 128 and up, gain 5.6–16% raw.
- **Compressed sizes barely move.** gzip turns a uniform leaf into a few bytes, so delivery size gains under 1%.
- **The real gain is GPU and pool memory.** Pool images are raw: WDAS at 256³ is 1.7 MB smaller as FLOAT.
- Previews at 48 gain nothing: at that ratio no 8³ block of the box filter is exactly uniform.

Measured with an uncommitted script over `packages/vdb/dist` (default vs `collapse: false`, gzip via Node `zlib`).

## K4.13 (a): `levelSetSampler: 'mjurczyk'`

`wvdb/level-set.ts` (new) ports his `sampleLevelSet` (`src/openvdb/utils/levelSet.js`) and `sampleLevelSetGrid`'s band
limit (`src/wvdb/bake.js`). It carries the header "Portions derived from mjurczyk/openvdb (MIT), commit 75e7345" and
keeps his arithmetic order:

- each texel is a trilinear sample near the surface, or the nearest voxel far from it;
- when texels are larger than a voxel, a texel whose 8 corners change sign is the mean of 4×4×4 sub-samples;
- a voxel's distance is its value clamped to ±b when active, and ±b by sign when inactive;
- finally `|v| < b` is clamped to `b − 2b/(2^bits − 1)`.

`BakeWvdbOptions.levelSetSampler: 'spec' | 'mjurczyk'`; the default stays `'spec'` (V17). Sources gain an optional
`index` (world→index map, inverse Jacobian, integer voxel lookup) and `grid` member. `wvdbSourceFromVdbGrid` and
`wvdbSourceFromNanoVdb` fill both.

**Result:** `vdbToWvdb(…, { levelSetSampler: 'mjurczyk' })` reproduces his committed `utahteapot.wvdb` and
`venusstatue.wvdb`:

- the header is identical with offsets zeroed, including `meanDensity`/`nonZeroVoxels`;
- **every inflated chunk is byte-identical** (6/6 and 6/6);
- the finest LOD has 0 mismatches out of 614,400 and 179,968 voxels.

With `'spec'`, 28,293 and 16,279 voxels differ. The NanoVDB path (`buildFromVdb` → `nanoVdbToWvdb`) gives the same
bytes as the `.vdb` path.

Tests (`test/tools/wvdb-k413.test.ts`):

- **Teapot without the env var.** A new `fixtures/wvdb/utahteapot.wvdb.digest.json` (header + inflated-chunk
  SHA-256, like the smoke digest; his file is not committed) lets the teapot test run from our pinned
  `fixtures/vdb-samples/utahteapot.vdb`. Its SHA-256 equals his header's `source.sha256`.
- **With `MJURCZYK_OPENVDB_DIR`.** Venusstatue is reproduced from his checkout, and the digest is checked against his
  file.
- **Synthetic sphere level set.**
  - Values stay in range, inside the band limit, and are ±b far from the surface.
  - Sub-voxel texels equal an independent trilinear computation.
  - Coarse texels differ from the spec point sample.
  - `'spec'` stays the default, byte for byte.

## K4.13 (b): page-by-page decode in `WvdbStreamReader`

The reader now decodes **chunk by chunk** instead of buffering every byte up to the last LOD:

- chunks decode in file order (sorted by offset), each as soon as its last byte arrives;
- the reader keeps only the bytes from the next undecoded chunk onward;
- LODs still complete coarse first, even if a file puts a finer LOD's chunks first.

New options and members:

- **`partialLods: true`** also emits `{ lod, levels, complete: false, chunk }` after every chunk. `levels` are the
  LOD's live in-progress objects: later pages fill the same arrays. New `bricksDecoded` / `pointsDecoded` fields on
  the levels say how much is in, and a page's bricks are `brickIndices[first .. first + count)`. Voxels of bricks not
  yet decoded hold the background. His kernel upsamples the coarser LOD there; that is renderer work (follow-up).
- **Memory.** `bufferedBytes` / `peakBufferedBytes` are exposed. The peak is at most the largest chunk (or the
  header) plus one push; the test checks it at push sizes 1, 97, 1000 and 65,536.
- **`end()`** throws `WvdbFormatError` naming the missing LOD, or the header if it never completed.
- After any error, every later `push`/`end` rethrows it.
- **Hostile input** (the K4.1 bar: reject before allocating):
  - `maxHeaderBytes` (default 16 MiB) is checked once 12 bytes are in.
  - Every chunk's compressed length must be at most `wvdbChunkByteLimit(inflatedMax) = n + ⌈n/1024⌉ + 1024`. zlib's
    `compressBound` is about `n + n/4096 + 13`, so any deflate encoder fits. This is checked when the header parses,
    so a hostile length is never buffered.
  - Inflate stays bounded, as before (`inflateWvdbChunk`).
  - Added in the decoders: a second mask chunk for one LOD is an error, and a mask/pages mismatch is caught when the
    LOD finishes.
- `decodeWvdbLod` / `readWvdb` use the same incremental decoders. Output is unchanged (all K4.3 tests pass), except
  for the new `bricksDecoded`/`pointsDecoded` fields. Pages are placed at their file-order position (`c.first`), so
  out-of-order decoding keeps `brickIndices` in file order.

Tests: a fixture rewritten with 3 bricks per page (many pages per LOD).

- One partial event per chunk, in file order. The final values and `brickIndices` equal `readWvdb`'s.
- Mid-LOD, every voxel is either its decoded value or the background, according to the bricks decoded so far.
- Without `partialLods`, there is still one event per LOD.
- Points grids stream too.
- A file with LOD 2's chunks first still completes LODs as 0, 1, 2.
- Hostile cases:
  - an oversize header, at once and with the preamble split over pushes;
  - an oversize chunk length;
  - a corrupt chunk, with the rethrow afterwards;
  - truncation (`end()`);
  - swapped masks;
  - 200 random single-byte corruptions: each is a `WvdbFormatError` or a clean decode, never another error.

## K4.13 (c): `sampling: 'box'`

- **`BakeWvdbOptions.sampling: 'nearest' | 'box'`.** The default stays `'nearest'`, his point bake.
- **What `'box'` does.** It runs `resampleDense` (new, exported from `nanovdb/resample.ts`). That is K4.4's
  `resampleGrid` box filter: the same axis tables, candidate leaves and three 1D passes, now factored into
  `filterLeaves`. It runs on his lattice: texel `j` is centred at `min + ((j + ½)/X)·size` over his voxel-centre box.
- **Output.** `resampleDense` returns dense values (x fastest) and an `active` flag: the footprint touches an active
  source voxel. Voxels outside every emitted leaf get the background.
- **Zero-size axis.** Unlike `resampleGrid`, a box with zero size on an axis (one voxel thick) is allowed; that axis
  takes the nearest voxel.
- **Level sets.** With the `'spec'` sampler, level sets apply §8 using the filtered active flag. The `'mjurczyk'`
  level-set sampler ignores `sampling`.

Measured mass ratio (texel sum × texel volume ÷ source mass; his default lattice; pre-quantization) and file size:

| Source | Resolution | Dims | Nearest | Box | `.wvdb` nearest / box (KiB) |
|---|---:|---|---:|---:|---|
| smoke | 32 | 16×32×16 | 1.019 | 1.000 | 4.8 / 5.6 |
| smoke | 64 | 32×64×32 | 0.995 | 1.000 | 30.1 / 33.6 |
| smoke | 128 | 64×128×64 | 0.999 | 1.000 | 228.0 / 243.6 |
| bunny_cloud | 32 | 32×32×24 | 1.027 | 1.000 | 7.4 / 9.7 |
| bunny_cloud | 64 | 64×63×49 | 0.998 | 1.000 | 45.2 / 56.3 |
| bunny_cloud | 128 | 128×127×97 | 1.002 | 1.000 | 312.4 / 370.7 |

What the table shows:

- Box conserves mass exactly at every resolution.
- Box files are 7–31% larger: smoother values make more bricks vary, and quantized codes compress worse.
- The default stays nearest. Box vs nearest needs a render A/B (CLAUDE.md "build both, then decide"); I suggest
  folding it into K4.19.

Tests:

- A 2× downsample on an aligned box is the exact 2×2×2 mean.
- On a 3-voxel texel lattice, box conserves mass (ratio 1 to 4 decimals against the box-covered mass) and nearest
  does not.
- The baked and decoded box `.wvdb` matches the dense values to within 8-bit quantization.
- A one-voxel-thick box works.
- Clear errors for a missing `grid` and an unknown `sampling`.
- Smoke: box mass is within 1%, closer than nearest.
