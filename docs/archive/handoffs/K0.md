# K0 handoff: re-foundation

Moves only; no behaviour change. Three v1 workspace packages became one published package, `@pmndrs/vdb`
(`packages/vdb`, version `0.0.0`, unreleased), built by a single `tsc` into `dist/{core,tools,three}`. Layout per
D20: one package with relative imports between layers, not three bundled packages.

Entry points: `@pmndrs/vdb` -> `dist/core/index.js`; `@pmndrs/vdb/tools` -> `dist/tools/index.js`;
`@pmndrs/vdb/three` -> `dist/three/index.js`; `@pmndrs/vdb/pnanovdb.wgsl` -> `vendor/pnanovdb.wgsl`.
`three` is an optional peer (`>=0.178.0`); `fflate` is the only runtime dependency. The old index of nanovdb-wgsl
had no GPU code beyond the WGSL URL, so core is small today; K1 fills it.

Source resolution: exports point at `dist/` only. In-repo, `tsconfig.base.json` `paths` and the aliases in
`examples/vite.config.ts` and `vitest.config.ts` map the four specifiers to source. No `development` condition.
In-package code uses relative imports (`src/three/*` imports `../tools/index.js`).

Also updated: `examples/` (deps, vite aliases, tsconfig reference, all imports), `e2e/` (comments only),
`scripts/` (generator output paths, `dist/tools/...` imports, wgsl path), `experiments/picovdb-spike` (import
paths; its 17 tests still pass), root `tsconfig.json`, `package.json` (`pack:dry` now packs `@pmndrs/vdb` only),
README package table/links, `fixtures/README.md` pointer. `ci.yml` needed no change (it calls the root scripts).
Generated headers (`stride-tables.generated.ts`, `pnanovdb-constants.generated.wgsl`) and their generators carry
the new paths; regenerating produces no diff.

## Boundary rule (K0.3)

`packages/vdb/test/boundaries.test.ts` scans `src/core/**` and `src/tools/**`:
- core must not import `three`, `three/*`, `src/three` or `@pmndrs/vdb/three`. Core may import tools.
- tools must not import `three`, `three/*`, `src/core`, `src/three`, `@pmndrs/vdb` or `@pmndrs/vdb/three`.
- three may import both.
It was proven by adding `import "three"`, `import "../three/grid.js"` to core and `import "../core/index.js"` to
tools: 2 of 4 tests failed naming each offender; the imports were removed and all 4 pass.

## Surprises

- Playwright 1.5x wants `chromium_headless_shell-1228`, which is not installed here (1208, 1234, 1243 are). e2e and
  `check-wgsl-compile.mjs` ran with `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` pointing at the 1243 headless shell.
  `playwright install` would also work.
- The root `vitest.config.ts` `projects: ["packages/*"]` does not inherit root aliases; tests use relative
  imports into `src/`, so no per-package vitest config was needed.
- Test fixture paths gained one `../` (`test/<layer>/` is one level deeper). Script libs referenced from tests the same.
- The v1 README claimed a `development` export condition; the root README now describes the real mechanism.
- STATUS.md still names the v1 tarballs in `artifacts/npm`; left as history.

## For the pathtracer

Its importer used `packages/vdb-web-tools/dist/index.js` (via `WEBVDB_DIR`). Use
`${WEBVDB_DIR}/packages/vdb/dist/tools/index.js` after `pnpm build` (same exports as the old vdb-web-tools, plus
`NanoVDBFile`, `readValue`, `sampleTrilinear`, `probeCoords`). As a published dependency it will be
`import ... from "@pmndrs/vdb/tools"`. Per D19 nothing here was changed to suit it.
