# K6.5 handoff: volume shadow maps on meshes and the emission light in the core

Design: [K6-core-renderer.md](../../dev/design/K6-core-renderer.md) §2.6, §3.3, §3.8 (now with "K6.5 as built" notes),
D34. Builds on [K6-2.md](./K6-2.md) (the 'frame' shadow grid the maps march), [K3-6.md](./K3-6.md) (the TSL port this
mirrors) and K7.1 (V74: drawn-state lookups, the scene-only budget).

**Landed:** K6.5 whole (core kernels, twins, receivers, emission colour data + hook, the `./three` `backend: 'core'` path
for the volume shadow filter and `VDBFrameEmissionLight`). **Not landed: K6.5b** (mesh → volume occluders); its remaining
scope is under Follow-ups.

## Design changes (please review)

1. **Receivers take the map and its view** (`vdbVolumeShadow(map, smp, view, world, viewDepth)`), not `light: u32`: a
   host binds a dynamic number of maps, so fixed bindings per light do not exist. Grey `f32` until K6.4.
2. **`VDBVolumeShadowMap.view` is a uniform buffer** of the drawn state (the core rewrites it each update) and `drawn`
   keeps per-layer `origin` / `far` (each cascade has its own).
3. **The emission LUT is bound in group 1** of the kernels with an emission source (not group 0, where K6.2b's
   environment buffer goes); `VdbFrameGroup` gains `emitters`.
4. **Hook signature** `vdbUserEmissionColor(t, temperature)` (t normalized, kelvin second) instead of `(t, emission)`
   (the emission value is t). A hook still validating draws white; `prepare()` awaits validation.
5. **Maps of lights absent from the frame are freed** (his keep a hidden light's map, disabled). `./three` only drops
   lights three does not draw either, so no receiver reads a freed map.
6. **One emission probe set per core renderer** (the first core `VDBFrameEmissionLight` in the scene; his: each light).
7. **The adapter's core update runs once per render from the first receiver's `updateBefore`** (`coreFrame`), so the
   maps and the receivers' drawn view come from the same update (see Traps).

## DIVERGES rows (provisional, from V100; source mjurczyk 75e7345 unless noted)

- V100 — K6.5: volume shadow maps are core compute kernels, one dispatch per piece, texels from the drawing camera's
  inverse view-projection (cascades as 2d-array layers; point maps 6 layers sampled through a cube view), not fullscreen
  passes into a 4-tile atlas / `CubeRenderTarget` (`FrameVolumeShadowMaterial`, `FrameVolumeShadows` L72–103, L788–828).
  Same values (A/B shadow term max 0/255).
- V101 — K6.5: receivers read the drawn view from a per-map uniform buffer the core writes (`vdbVolumeShadow*`; his
  62a6e3e by construction); a light absent from `frame.lights` frees its map (his keep it, disabled, `isVisible`).
- V102 — K6.5: the emission direction pass is one workgroup per (direction, emitter) with one lane per ray and a
  workgroup tree reduction (his fragment loops the 64 rays); probes are a stacked 3D texture read with hardware trilinear
  (his 2D atlas with a z lerp). f32 summation order only (A/B light term max 1/255).
- V103 — K6.5: emission colour is data (a LUT row over log temperature: his blackbody table pre-blended at the soot
  exponent, or the caller's) plus an optional validated WGSL hook (`VDB_BAD_WGSL`); supersedes V24/V62 in the core.
  `./three` maps `vdbFrameBlackbodyEmission` to its table's row; other TSL hooks draw white with `backend: 'core'`.
- V104 — K6.5: with `castShadows` in 'volume' lighting the core draws every shadow grid cascade (his
  `renderShadowDensity(onlyLast)` draws the last); the last cascade is the same, the rest is cost only.
- V105 — K6.5: one emission probe set per core renderer, from the first core `VDBFrameEmissionLight` (his: each light
  computes its own probes).

## Follow-ups

- **K6.5b (not started)** — mesh → volume shadows. Remaining scope, precisely:
  1. Core input `VDBFrameInput.occluders` (typed since K6.1, warned): per map `{ light, depth: GPUTextureView ('2d-array'
     view; cascades / cube faces as layers), viewProjection[], orthographic, bias, reversedDepth }`; up to 4 maps bound
     per kernel in fixed slots (`texture_depth_2d_array`, 1×1 placeholders, a comparison sampler), a uniform with the
     count, matrices (≤ 4 maps × ≤ 4 layers) and per-light occluder index (`VdbFrameLights.falloff.z` is free).
     Watch the limits test: a dense 'frame' gather samples 8 + transmittance + LUT = 10 textures; +4 occluders is 14
     (WebGPU default 16; the test's cap is 12, so either raise it with a reason or stack the 4 placeholders).
  2. Twin `vdbFrameOccluderVisibility` (1 tap or 2×2 PCF as the host's filter) and its use in
     `vdbFrameTransmittanceVoxel3d` (scattered / total × voxel visibility, direct unoccluded), the fused gather twin
     (direct × visibility at the froxel's visible position) and the 'volume' march twin (both terms at the lit position).
  3. Kernels: `vdbFrameTransmittanceCs`, the 'frame' gather (`vdbFrameDensitySums` / `vdbFrameLightFroxel`) and the
     'volume' gather (`vdbFrameVolumeFroxel`); `settings.occlusion` (default true when maps are given).
  4. `./three`: pass three's light shadow maps (`light.shadow.map.depthTexture` → backend texture, a three-internals
     self-test; the shadow camera's view-projection, `shadow.bias`); three renders them inside its frame, so the core
     reads the previous render's map (document, or order the core update after three's shadow pass).
  5. Gate: a box between the sun and the bunny cloud darkens only the cloud behind it (k3-frame scene + a mask of the
     box's shadow volume); the parity scenes unchanged with no occluder; twins + mutations in `?probe=frame` /
     `?probe=gather` with a synthetic depth map.
- K6.4: spectral maps (his output 1 / per-channel receivers) and spectral emission are not in the core maps yet.
- The adapter's cube stand-in relies on three r187's `CubeTextureNode` x flip on WebGPU (passed in with x negated); a
  three bump must re-check it (add to the core-texture self-test if three changes it).
- `prepare()` builds every gather with each hook a source's volumes use; it does not know the emission light settings
  (the reduce / probe kernels are built for any emitting source).
