### How a module is built

API layer text (final names) → its `vdb_*`/`VDB_*` identifiers that map to vendored declarations are the roots →
closure over the table, with overrides applied → second pass that keeps only the type-table fields the closure
reads → emit in file order, renamed → `vdb_load` → API layer. Head: the SPDX banner, the `slot` declaration, and
only the layout constants the body references.

Public WGSL (`read`): `vdbGridCount()`, `vdbGridType(g)` (0 for a dead or out-of-range id), `VdbAccessor`,
`vdbAccessorInit(g)`, `vdbReadValue(&acc, ijk)`, `vdbIsActive(&acc, ijk)`, `vdbIndexMin(g)`, `vdbIndexMax(g)`.
`sample` adds `vdbWorldToIndex{,Dir}`, `vdbIndexToWorld{,Dir}` (record affines, 12 loads), `vdbSample(&acc, xyz)`,
`vdbRayClip(g, o, d, &t)`.

### Deviations from the design note

- **Type table, one step further than §3.3:** besides cutting rows to the compiled types, fields no emitted
  declaration reads are written `0u` and equal rows share a branch (Fp4/8/16/N then share one row; Float+Fp8+FpN
  has two). Saves ~290 B on multi-type modules. Logged in VENDOR.md.
- **`read_float_typed` with no Float compiled:** the last Fp type is the unconditional fallthrough (no branch for
  single-Fp modules).
- **`VdbAccessor` gains `lo`/`hi` (vec3f)** only when `profile: 'sample'` and `outside: 'zero'`: the index bbox
  `[min, max + 1]` cached at init, so `vdbSample` does not need the grid id. Otherwise it is exactly
  `{ buf, gridType, ok, inner }`.
- **`outside: 'zero'`** returns 0 when the sample point is outside `[indexBBoxMin, indexBBoxMax + 1]` (the same box
  `vdbRayClip` uses). There is no CPU twin for it yet; K1.6 should confirm the convention against the pathtracer's.
- **`sampler: 'nearest'`** reads `vec3i(floor(xyz + 0.5))` (NanoVDB `SampleFromVoxels` order 0 rounds). No CPU
  twin yet either.
- **`vdbRayClip`** returns `hit && t.x <= t.y` (the clipped interval is non-empty), not the vendored
  `hdda_ray_clip`'s infinite-ray test.
- **No sub-object pointers.** The API copies `acc.inner` to a local, passes `&local`, and writes it back, because
  passing `&(*acc).inner` needs WGSL `unrestricted_pointer_parameters`, which not every implementation has.
- **`profile: 'march' | 'majorant'`** are in the type and throw `VDB_BAD_OPTION` ("lands in K1.4b").
- **`vdbModuleEntries` default visibility** is `COMPUTE` (bvh's default).
- **Not exported from `core/index.ts`:** `VDB_GPU_LAYOUT_VERSION` (K1.3a owns it; exporting it from both would
  conflict on merge).
