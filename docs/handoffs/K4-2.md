# Handoff: K4.2 — vector and point grids in the `.vdb` parser (plus K4.7)

The pure-TS `.vdb` parser in `@pmndrs/vdb/tools` now reads:

- vector grids (`vec3s`, `vec3d`, `vec3i`), which build NanoVDB `Vec3f` grids;
- point data grids (`ptdataidx32`), which decode to a point list;
- OpenVDB 12.1 half-float grids that omit empty value arrays (K4.7).

Every sample in `fixtures/vdb-samples` now parses, all grids included.

Format authority: OpenVDB and NanoVDB at the repo pin `a532de55`. Headers used: `io/Compression.h`,
`tree/{Root,Internal,Leaf}Node.h`, `Grid.h`, `points/{PointDataGrid.h, AttributeArray.h, AttributeSet.cc,
StreamCompression.cc}`, `math/QuantizedUnitVec.*` and `nanovdb/tools/GridStats.h`. They were fetched read-only to
the scratchpad; the sparse checkout only has NanoVDB.

## What changed

All changes are in `packages/vdb/src/tools/**` and `packages/vdb/test/tools/**`.

### Parser

**Value formats** (`vdb/compression.ts`). A `ValueFormat` has `components` (1 or 3) and a component kind (`f32`,
`f64`, `i32` or `u32`).

- `readCompressedValues` reads `numValues * components` scalars. That covers raw, zip and Blosc storage, half or
  full width, and active-mask expansion with the inactive fill values (which are written full width even in
  half-float grids).
- `readFullValue` reads the root background and root tile values, which are always full width.
- Half storage is honoured only for real types, following `RealToHalf<T>::isReal`. An integer grid saved "as
  half" stays full width.
- Values are decoded into a `Float32Array`. That is exact for f32, and for i32/u32 below 2^24. f64 is narrowed.

**K4.7: the rule from the source.** `io::HalfWriter<true, T>::write` and `HalfReader<true, T>::read` both
`return` when `count < 1`, so an empty half-float array has no payload at all: no Blosc or zip i64 either.

- Full-width and integer arrays go through `readData`. With Blosc or zip, that still writes the size field for
  count 0. bunny_cloud stores a 16-byte empty Blosc frame there.
- So the parser reads nothing when `half && activeCount < 1`. It does not use a retry or a writer-version guess.

The K4.1 handoff guessed that "older writers write the i64 for zero counts". That was wrong:

- The v222 half-float samples (sphere, cube, teapot, smoke) are not zip-compressed (compression = active mask
  only), so count 0 reads nothing under either convention.
- I checked this by dumping the bytes at every empty node.

**Grid API** (`vdb/types.ts`, `vdb/grid.ts`). This is a breaking type change: `VdbGrid` is now a discriminated
union on `valueType`.

| Type | `valueType` | `components` | `background` | `readValue().value` | Extra fields |
|---|---|---|---|---|---|
| `VdbFloatGrid` | `float` | 1 | `number` | `number` | — |
| `VdbVec3Grid` | `vec3s`, `vec3d`, `vec3i` | 3 | `[x, y, z]` | `[x, y, z]` | — |
| `VdbPointDataGrid` | `ptdataidx32` | 1 | `number` | the voxel's end offset | `pointCount`, `attributes`, `groupNames`, `points()` |

- Vector leaves hold 1536 interleaved values. Vector tiles are `[x, y, z]`.
- New exported types: `VdbFloatGrid`, `VdbVec3Grid`, `VdbPointDataGrid`, `VdbPointList`,
  `VdbPointAttributeInfo`, `VdbPointAttributeArray`, `VdbValueType`, `Vec3Tuple`.

**Point data grids** (`vdb/points.ts`, new). This follows OpenVDB's multi-pass I/O (`Grid::readBuffers`): a
`u16` pass count, then the tree walked once per pass.

- Per leaf, the passes read:
  - the voxel-buffer size;
  - the descriptor (shared via header bit 1) and the array metadata;
  - page headers per attribute;
  - the voxel buffer (raw 0xFFFF or Blosc);
  - the page bodies, or non-paged buffers.
- Paged streams follow `PagedInputStream` exactly: a page header is read when an array starts a new page.
  - Blosc pages padded to 48 bytes are accepted, per the rule in `bloscDecompress`.
  - Page bytes stay views into the file until `points()` runs.
- `points()` returns:
  - world `positions`: index-to-world of (voxel ijk + P);
  - every other decodable attribute;
  - group membership by name (`Descriptor::groupIndex`: sorted `uint8`/`grp` arrays, bit = offset % 8);
  - `skipped`: attributes whose type and codec it cannot decode.
- Codecs:
  - `null`, including all OpenVDB scalar, vec, quat and mat type names;
  - `trnc` (half, int16);
  - `fxpt8/16` and `ufxpt8/16`, with OpenVDB's f32 arithmetic;
  - `uvec`: `QuantizedUnitVec::unpack`. The 8192-entry weight table is generated, not copied, and equals
    OpenVDB's table bit for bit (scratch check against `QuantizedUnitVec.cc`);
  - `str`, as raw u32 indices.
- Uniform and constant-stride arrays are handled. Variable-stride arrays are skipped.
- Validation: end offsets must be monotonic, and every array's size must equal the leaf's point count.

**Bug fix, pre-v222 leaves.** `LeafNode::readBuffers` reads the value mask *before* the origin and buffer count.
Our reader had them the other way round, and the synthetic writer mirrored that. No corpus file is pre-222.

### NanoVDB

- **Vec3f build** (`nanovdb/{bytes,leaf-codec,tree,stats,serialize,build-from-vdb}.ts`). It has:
  - `VEC3F_LAYOUT` (GridType 6);
  - root 96 bytes, root tile 32 (value at 20), table stride 16, upper 532,544, lower 66,624, leaf 6,272 (table at
    128);
  - all checked against the vendored stride tables.
- **`VEC3F_LEAF_CODEC`**. `buildFromLeavesDetailed` and `buildTreeFromLeaves` take a `components` setting. Tile
  and background values are `number | [x, y, z]` (`TileValue`).
- **Stats follow `GridStats.h` `Stats<Vec3f, 1>`** (rank 1):
  - `min`/`max` are the *vectors* with the least and greatest f32 `lengthSqr()`, first one wins on ties;
  - `ave`/`std` are the mean and population std of `lengthSqr()`, not of the components. They are f32
    (`FloatTraits<Vec3f>` is float);
  - tiles are weighted by the child slot count, as before;
  - the class is `Vec3StatsAccumulator`.
- **`buildFromVdb`** dispatches on the value type:

  | Source grid | NanoVDB result |
  |---|---|
  | float | FLOAT |
  | vec3s, vec3d, vec3i | Vec3f |
  | point data | `VdbUnsupportedError` |

  The grid class maps `staggered` to `Staggered` (3).
- **CPU oracle.** New `readValueVec3(image, ijk)` and `sampleTrilinearVec3(image, xyz, { outside })`. The second
  is componentwise, with the same taps and lerp order as `sampleTrilinear`. `readValue` on a VEC3F image throws
  and points to `readValueVec3`.
- **Other tools.**
  - `inspect` reports Vec3f with correct section sizes.
  - `writeNvdb` already carried any grid type.
  - `NanoVDBFile` still rejects Vec3f, which is in scope for later (GPU and pool are out of scope).
- **`.wvdb`.** `wvdbSourceFromVdbGrid` throws for non-float grids. `vdbToWvdb` bakes float grids only and skips
  vector and point grids (his CLI bakes them; not ported).

### Independent checks used

- **OpenVDB's own metadata:** `file_voxel_count` and `file_bbox_min/max` for every grid of every sample.
- **Narrow band:** level-set active values satisfy |v| <= background (bunny, icosahedron). Fire's active
  density and temperature are > 0.
- **His `sphere_points.wvdb`,** decoded by his reader from his copy of the `.vdb`:
  - header `count` 9802;
  - header bbox equal to our decoded positions' bbox to the last f32 bit (asserted with no env var);
  - with `MJURCZYK_OPENVDB_DIR`, every point of every LOD, in his LOD order, is within 1.53e-5 of ours (bound
    2/65535; his chunks are 16-bit quantized);
  - his `.vdb` (141,340 bytes, a different SHA from our fixture) decodes to bit-identical positions.
- **waterfall_points:**
  - voxels with points = active voxels = `file_voxel_count`;
  - all 9,525,253 `id`s are unique;
  - Cd values are exact 8-bit codes;
  - points stay inside the file bbox ± half a voxel.
- **NanoVDB GridStats:** the `Stats<Vec3f,1>` semantics, re-derived by brute force in the tests.

## Open issues

1. **No native Vec3f parity.** Our Vec3f image was not compared with `nanovdb_convert` output (no Docker or
   native tools here). The stats semantics come from reading `GridStats.h`. The f32 `lengthSqr` might differ
   from native by an FMA contraction in rare ties.
2. **`points.ts` is not hardened against hostile input** the way K4.1 hardened Blosc.
   - What is in place: decompression is capped by the page header and array sizes, and counts are checked.
   - What is missing: a page header can still claim up to 2 GiB of output, and a uniform array's `size` is
     unbounded by bytes.
3. **Asset-gated tests that fail only with `MJURCZYK_OPENVDB_DIR` set.** In K4.3's `wvdb-read.test.ts`, 3 such
   tests fail. Nothing here touches that code. The causes:
   - our symlinked `fixtures/vdb-samples` now holds `sphere_points.vdb` and `bunny_cloud.vdb`, and `vdbSample()`
     prefers ours over his;
   - ours are different files from the ones his `.wvdb` headers hash, so the source SHA check fails;
   - a level-set test takes ~7 s against the 5 s default timeout.
4. **Inactive values in compressed arrays are still 0** (K4.8, unchanged), now also for vectors.
