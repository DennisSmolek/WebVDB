# K4.8 / K4.9 / K4.12 / K4.14 handoff

OpenVDB parser and NanoVDB serializer correctness leftovers. Format authority: OpenVDB
`io/Compression.h` (`readCompressedValues`, `MaskCompress`) at the pinned version.

## K4.8 inactive leaf and node values

`readCompressedValues` (`src/tools/vdb/compression.ts`) now restores inactive values exactly as OpenVDB:

- `inactiveVal1 = background`
- `inactiveVal0 = (meta == NoMaskOrInactiveVals) ? background : -background`
- metadata 2, 4, 5 read `inactiveVal0` (and 5 also `inactiveVal1`) at full width from the stream
- the selection mask (3, 4, 5) picks `inactiveVal1` where set, `inactiveVal0` elsewhere

Before: the fill defaulted to 0 and only mode 1 used the background. Applies to leaves and to internal-node
tile arrays (same function), scalar and vec3. `background` is now an array (`components` entries); the old
blosc tests passed a bare number and were fixed.

Tests: `test/tools/inactive-values.test.ts`, one case per metadata mode (0 to 5, plus 6) for scalar and vec3;
bunny, utahteapot and icosahedron: every inactive leaf voxel is exactly +/-background (and some are negative).

## K4.9 inactive internal tiles

- `TileData.active` (`vdb/tree.ts`); root tiles keep every tile, active or not.
- Upper and lower inactive tiles are kept when their value differs from the background. An inactive tile equal
  to the background reads identically to no tile, so it is not stored (a 32768-slot upper node would otherwise
  add thousands of records). This is lossless for `readValue` and for NanoVDB bytes.
- `readValue` returns the tile value with `active: false`. `iterTiles()` stays active-only (resample, quantize,
  march keep their meaning); new `VdbGrid.iterInactiveTiles()`.
- NanoVDB: `TileInput.active?: false` writes the value into the lower/upper slot with no value-mask bit, and a
  root tile with `state = 0`. Inactive tiles are excluded from stats, bbox, `tileCounts` and the active voxel
  count (the same rule as OpenVDB's active-only counts).
- `buildFromVdb` passes active then inactive tiles. It tolerates grid objects without `iterInactiveTiles`.

Tests: utahteapot interior reads `-background`, inactive, in the parse and in the NanoVDB image; synthetic
file with inactive tiles at root, upper and lower level, and a background-valued one that is dropped.
`active-tiles.test.ts` expectations moved from "inactive dropped" to "inactive kept".

## K4.12 root key order

Root table entries are sorted by the u64 NanoVDB key (`coordToKey`, bigint compare), not by signed origin.
Negative coordinates now sort after non-negative ones. Test with six negative and positive origins.

## K4.14 hardening

- `parseVdb` rejects file versions above 225 with `VdbUnsupportedError` (OpenVDB's `OPENVDB_FILE_VERSION`).
- `readMetadataMap` returns a null-prototype object. Public type unchanged (`Record<string, MetadataValue>`),
  but `.hasOwnProperty` and `.toString` do not exist on it; use `Object.hasOwn`, `in`, `Object.keys`.
  `grid.metadata` and file metadata are built this way. Test: a metadata name `__proto__` stays an own key.

## Effect on NanoVDB output

Level-set `.vdb` files now produce different NanoVDB bytes: inactive leaf voxels are +/-background instead of 0,
and interior inactive tiles are written. Fog volumes with a zero background are unchanged. See the report for
the e2e golden check.

## DIVERGES

V6 can be removed (both clauses fixed). V5 is unrelated (quantize).
