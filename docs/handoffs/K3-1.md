Public entry (`@pmndrs/vdb/three`): `VDBFrameVolume(source, props)` (his `FrameVolume` props for the ported
subset, plus `frameRenderer` and `bbox`) and `VDBFrameRenderer` (his `frameRenderer.settings`: `width`, `height`,
`pixelsPerFroxel`, `depth`, `subSteps`, `near`, `far`, `fadeRadius`, `jitter`, `temporal`, `lighting`,
`srgbBlending`, `multipleScattering`, `spectral`), `vdbFrameRenderer()` (shared instance), the two materials, the
view/layout/phase helpers and `vdbFrameChunks`. Usage:

```ts
const source = vdbDenseTextures(wvdbDenseVolume(readWvdb(bytes)));
const volume = new VDBFrameVolume(source, { phase: "dual-lobe", extinction: 100 }); // box = the .wvdb bbox
scene.add(volume);
renderer.render(scene, camera); // the proxy's onBeforeRender draws the froxels
```

Density is read only through `vdbVolumeNodes` (K3.0's `createVolumeNodes()` shape): `boxSegment`, `getLod`,
`sampleExtinction`, `sampleAlbedo`, `sampleEmission`, `boxExit`. Step 2 swaps the source.

Multiple scattering: `false` and `true` (1D diffusion) are in the same pass graph and both ported; `'neural'`
gives the same value as `true` in `'volume'` lighting (his network runs only in `'frame'` lighting), so it is
accepted. `'two-sided'` and `'octaves'` are Step 4 (they warn and run as `true` / `false`).

## Departures (DIVERGES rows, provisional IDs K3.1-a…e; coordinator assigns V-numbers)

1. **K3.1-a** One inject material per volume source (source compiled in; mask presence compile-time in
   `getSampledLod`) instead of one shared material with per-volume texture uniforms. Values identical.
2. **K3.1-b** Feature subset: `'volume'` lighting, grey; ambient/directional/point/spot; HG + dual-lobe; MS off and
   1D. Not yet (each warns once): `'frame'` lighting, temporal, hemisphere, light probes, scene environment, Mie
   (renders isotropic), octaves, two-sided, spectral, mesh shadows, emission LUT.
3. **K3.1-c** `VDBFrameVolume` takes a volume source and holds one volume; mean density from the source; no CPU
   conversion, multi-grid, instances, level sets or points.
4. **K3.1-d** Renderer defaults `lighting: 'volume'`, `temporal: false`, `multipleScattering: true` (his: `'frame'`,
   `true`, `'neural'`).
5. **K3.1-e** Added `renderFroxels()`, `holdFroxels`, `passHook` (per-pass timing) and the `emissionColor`
   pass-through.

Not departures (kept exactly as his, on purpose): the frame identity by `renderer.info.render.calls` (R1 §8
worried about it; in r187 `calls` counts `render()` calls, not draws, so it is sound), the WebGL-convention
`frustum.setFromProjectionMatrix` in the collector, `renderOrder 1e6`.

## Parity: why the gate needs new captures, and how to run it

His Step 1 scenes in the K3.0a list can't be matched by Step 1, whatever we port: on his examples page every
light setup keeps `scene.environment` (his HDR map), and a `FrameVolume`'s `lights` default includes the
environment, so even `lightSetup: 'dir'` lights the bunny from the environment ('directional' environment lights
from a PMREM readback, K3.4). `step1-lighting-volume` is environment-only; `step1-lights-directional` and
`step1-multiple-scattering-off` are `'frame'` lighting (K3.3). His JPEGs show it: the bunny is white from the sky.

So `scripts/k3/capture-reference.mjs` gains two scenarios, `step1-volume-dir-ms-off-isolated` and
`step1-volume-dir-ms-on-isolated`: the same GUI fields, then (his public API only, after the page is idle) every
FrameVolume gets `lights = 8` (directional only), every other mesh is hidden (grounded skybox, ground, props,
helpers) and the background is his init colour 0x598eff. The harness renders the same scenes; `compare.mjs` masks
to the volume's screen rectangle (from the harness sidecar `<scene>.json`) and gates only scenes with
`parityExpected: true` (the two isolated ones); the rest print as INFO with the reason.

Owner, once (K3.1a), on the hardware-GPU machine:

```sh
# 1. capture (K3.0a steps; the script now includes the *-isolated scenarios)
node scripts/k3/capture-reference.mjs --openvdb "$tmp/openvdb"           # or --scenarios step1-volume-dir-ms-off-isolated,step1-volume-dir-ms-on-isolated
# 2. his CC BY-SA bunny into the git-ignored fixtures dir
mkdir -p fixtures/k3 && cp "$tmp/openvdb/src/docs/examples/public/assets/bunny_cloud.wvdb" fixtures/k3/
# 3. one command: render ours (manifest cameras/matrices) and compare against the strict bar, heatmaps to artifacts/k3/diff
pnpm k3:parity
```

The harness reads the camera and volume matrices from `fixtures/k3-reference/75e7345/manifest.json` when the
scenario is there (else from his `frame.js` constants). Expected small differences, in order of likelihood:
MSAA (his page has `antialias: true`; the integrate quad's interior is unaffected, but the volume's own edge is
not geometry so this should be nil), hardware vs SwiftShader 8-bit filter weights (CLAUDE.md trap), half-float
froxel atlas rounding. If the heatmaps show a uniform offset instead, suspect the output path (ours: linear
HalfFloat target → CPU sRGB OETF; his: canvas output pass).

## Brief for Step 2 (K3.2): sparse source + LOD A/B

**Goal.** A `VDBVolumeSource` over the sparse pool with the same node shape, so `VDBFrameVolume` renders a
NanoVDB grid; A/B the LOD strategies (R1 §4.3): `none` (level 0 only), `coarse-pyramid` (compute-built dense
levels from L₀ = ⌈log2(maxTexels / pyramidMax)⌉, r16f, manual trilinear, levels 1…L₀−1 blended toward L₀),
`node-average` (trilinear over leaf/lower averages at levels 3 and 7). HDDA (`march` profile) in the inject shadow
march and a `vdbSrcMaxIn` early-out per froxel.

**Where.** `packages/vdb/src/three/volume-source.ts` gets `vdbSparseNodes(gridNode, grids, { lod })` returning
`VDBVolumeNodes` (same seven functions). The inject material already takes the source and its uniforms; generalise
its `source: VDBThreeDenseSource` to an interface with `channels`, `lodLevels`, `texels`, `stats` (the K3.0
`VDBVolumeSourceInfo`) plus a `nodes(uniforms, options)` factory, and make `VDBFrameVolume` accept either kind.
One VDB module per shader (CLAUDE.md): one inject material per pool, which K3.1-a already gives. Keep
`normalize: 'clamp01'` as a compat flag for the A/B; default unclamped (DIVERGES).

**A/B scenes.** (1) `bunny_cloud.wvdb` finest LOD converted to NanoVDB with identical voxels (sampler-only diff):
dense vs sparse `none` on the same harness scene, PSNR ≥ 38 dB; (2) `smoke.vdb` full-res and the WDAS quarter
cloud: flicker metric (mean frame-to-frame diff on a slow orbit) per LOD mode; per-pass ms (provisional) and GPU
bytes (source + pyramid). Harness: add `?source=sparse&lod=none|pyramid|node` to `k3-frame` and a `?orbit=N`
frame sequence; the CPU twins for the sparse sampler exist (`tools/cpu`), add one for the pyramid build.

**Acceptance.** `pnpm typecheck`, `pnpm build`, `pnpm test`, e2e: the K3.1 spec unchanged plus a sparse variant
(determinism, twins, occlusion), and the dense-vs-sparse identical-voxel PSNR. Do not touch `core/pool`,
`core/wgsl` size snapshot (unless on purpose), `VDBVolumeMaterial`, demos.
