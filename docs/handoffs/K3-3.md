`VDBFrameVolume` gains `densityMaterial` / `shadowDensityMaterial` (built on first use, disposed with it). New
public exports (`@pmndrs/vdb/three`): the seven materials, `VDBFramePass`, `VDBFrameRedrawStats`; (`@pmndrs/vdb/tools`):
`vdbFrameGridCascades`, `vdbFrameGridRange`, `vdbFrameCascadeCasters`, `vdbFrameUpdateGridSignatures` (+ state),
`VDBFrameEnvironmentLights` and the twins.

Usage:

```ts
const fr = new VDBFrameRenderer();
Object.assign(fr.settings, { lighting: "frame", shadowCascades: 4, phase: "dual-lobe", temporal: true, jitter: true });
const volume = new VDBFrameVolume(vdbSparseSource(grids, { density: id }), { frameRenderer: fr }); // or vdbDenseTextures(...)
scene.add(volume);
scene.environment = hdr; // 'directional' environment lights: 8 from a 64 x 32 PMREM readback (async)
renderer.render(scene, camera);
```

Both sources: the shadow density pass reads `vdbVolumeNodes(source).sampleExtinction(local, lod)` at the grid voxel's
lod; with the sparse source that is its coarse LOD (`'coarse-pyramid'` by default, D28), one r16f fetch at grid lods.
One VDB module per shader holds: each density / shadow-density material compiles only its source's `VDBGridNode`.
The grid signature includes a per-source id, `source.version`, `lodLevels` and the LOD mode (dense: the texture ids and
versions, his rule).

### Defaults (V33): kept

`lighting: 'volume'`, `temporal: false` stay. His default set is `'frame'` + temporal + `multipleScattering:
'neural'`; the network is Step 4. With `'neural'` our 'frame' lighting runs 1D diffusion on the scene light slots
(identical for environment-only scenes: his network only touches scene light slots, and with diffusion every
environment light goes to the environment grid), and warns. Flipping the default now would change users' images
twice (now, and again when the network lands), so K3.4 flips all three together. New settings carry his defaults:
`temporalBlend` 0.2, `shadowResolution` 64, `shadowCascades` 1, `shadowDistance` 512, renderer `phase`
'henyey-greenstein' (his demos set 'dual-lobe'), `environmentLighting` 'directional', `environmentSamples` 8,
`environmentShOrder` 1.

## DIVERGES rows (text for the coordinator; no IDs)

1. **mjurczyk `FrameShadowDensityMaterial` / `FrameDensityMaterial` (one shared material per pass; pool meshes swap
   each volume's textures and `frameUse*Map` flags into its uniforms)** → one density and one shadow-density
   material per volume source (the source compiled in, as the inject material); pool meshes take their volume's
   material and set its uniforms in `onBeforeRender`. Values identical. *simplification.* Revisit: many volumes with
   the same channel layout (compile count).
2. **mjurczyk `'frame'` lighting feature set** → grey only; multiple scattering `false` and `true` (1D diffusion);
   `'neural'` runs as `true` (warns; identical for environment-only scenes), `'two-sided'` as `true`, `'octaves'` as
   `false`; no grid mips (neural input), Lorenz-Mie renders isotropic, no mesh shadows (`castShadows`), no emission
   lights, no spectral groups. Hemisphere lights, light probes and environment lights are read by 'frame' lighting
   only ('volume' lighting still ignores them, warns). *simplification.* Revisit: K3.4 (neural, two-sided, octaves,
   Mie), K3.5 (spectral), K3.6 (mesh shadows, emission).
3. **mjurczyk `pushCasterMaps` / `renderEnvironmentGrid` signatures (texture ids and versions of six maps; the
   environment grid signature re-pushes every caster's maps, props and matrix)** → the caster signature pushes a
   per-source id, `source.version`, `lodLevels`, the LOD mode, and for dense sources the texture ids and versions;
   the environment grid signature pushes `castVersion` and the caster count (which change exactly when those caster
   values do). *extension (sparse source) / simplification.* Revisit: never.
4. **mjurczyk `core/frameGrid.js`, `core/frameEnvironment.js` (three `Box3`/`Vector3`, Float32 readback)** →
   engine-free in `tools` (plain `{x, y, z}` and `{min, max}`; three's objects fit); `VDBFrameEnvironmentLights`
   also decodes half-float readbacks and exposes a `settled` promise for harnesses. Values identical.
   *extension.* Revisit: never.
5. **mjurczyk `FrameRenderer` API** → added `redrawStats` (drawn / skipped renders of the shadow density,
   transmittance and environment grid passes) and pass names for `passHook` (`shadowDensity`, `transmittance`,
   `environmentGrid`, `density`, `lighting`, `temporal`). *extension* (extends the K3.1 API row).
6. **V33 text update**: "`VDBFrameRenderer` defaults to `lighting: 'volume'`, `temporal: false`,
   `multipleScattering: true`. K3.3 ported `'frame'` lighting and temporal; the defaults flip together when K3.4
   ports `'neural'`." Revisit: K3.4.

Not departures (checked, kept exactly as his): his fine cascades never reach the bunny with his demo camera (his
`shadow-cascades-4` scene renders one cascade; ours too, PSNR 107.8 dB between our default and cascades-4 isolated
renders); his transmittance redraws on every jittered frame; his 'frame' point/spot lights get three's
`getDistanceAttenuation` while 'volume' lighting's don't.

## Parity: how to run it (owner, K3.3a)

```sh
node scripts/k3/capture-reference.mjs --openvdb "$tmp/openvdb" --scenarios step3-default-dir-isolated,step3-shadow-cascades-4-dir-isolated,step3-shadow-grid-high-dir-isolated,step3-two-bunnies-dir-isolated,step3-environment-sky-midday-env-isolated,step3-default,step3-shadow-cascades-4,step3-shadow-grid-high,step3-two-bunnies,step3-environment-sky-midday,step3-shadow-cascades-4-asis,step3-shadow-grid-high-asis,step3-environment-sky-midday-asis
cp "$tmp/openvdb/src/docs/examples/public/assets/"{bunny_cloud.wvdb,sky-midday-HDR.jpg} fixtures/k3/
pnpm k3:parity
```

New isolate modes: `'frame'` (his sun only, `scene.environment = null`, meshes hidden, background 0x598eff) and
`'environment'` (no scene light, his UltraHDR map kept at intensity 0.4, skybox hidden). The manifest now records
`environment` (intensity, rotation) and the visible lights; the harness reads the intensity/rotation and every
captured volume matrix (the second bunny turns on a timer). The `*-asis` scenarios run his own JPEG sanity bar.
Expected differences, most likely first: MSAA on his canvas, 8-bit filter weights on hardware (CLAUDE.md trap), the
environment readback's half/float rounding (lights' directions are centroids, robust), and the async environment
readback (his page is idle when captured; the harness waits for the lights).
