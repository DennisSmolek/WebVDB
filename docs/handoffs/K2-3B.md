## API (before → after)

| v1 (`@pmndrs/vdb/three`) | core (`@pmndrs/vdb`) | three wrapper |
|---|---|---|
| `gridStats(device, grid, pnanovdbSource, { histogramBins })` → `Promise<GridStatsResult>` | `gridStats(device, pool, id, { histogramBins?, encoder? })` → `VDBReadback<VDBGridStats>` | `gridStats(renderer, pool, id, { histogramBins? })` → `Promise` |
| `decodeToAtlas(device, grid, src, { maxDim, filter, format, normalize, range })` → `Promise<{ data, dims, range }>` | `decodeToAtlas(device, pool, id, { …v1, encoder?, readback? })` → `VDBAtlasReadback` (`dims`, `range`, `buffer`, `read()`, `dispose()`) | `decodeToAtlas(renderer, pool, id, opts)` → `Promise<{ data, dims, range, texture: Data3DTexture }>` |
| `valueTransform(device, grid, src, wgslBodyOrPreset)` → `Promise<{ image }>` (GPU) | `applyValueTransform(pool, id, sourceImage, fn \| preset)` → new image, staged with `pool.replace` (CPU) | `valueTransform(pool, id, sourceImage, fn \| preset)` |
| `VALUE_TRANSFORM_PRESETS` (WGSL bodies), `resolveTransformBody`, `buildComputeShaderSource`, `buildValueTransformShaderSource` | `VDB_VALUE_TRANSFORM_PRESETS` (functions: `double`, `half`, `negate`, `clamp01`) | removed |
| `bboxSize`, `computeAtlasDims` | `tools`: `bboxSize`, `atlasDims` | removed |

- Readback contract: the tool records its pass (and the copy to a staging buffer) into `options.encoder`, or creates and
  submits its own encoder. Call `read()` after the submit; it maps, reduces, and frees every buffer the tool
  allocated. `dispose()` frees without reading. `readback: false` (atlas) keeps `buffer` (raw f32, x fastest,
  `STORAGE | COPY_SRC`) for the host's own passes until `dispose()`; `read()` then rejects without freeing it.
- Checks before any device work (`VDB_BAD_OPTION` unless noted): options; `pool.device === device`; the grid exists
  (`VDB_UNKNOWN_GRID`); it is resident (`pool.update`/`flush` ran after its `add`/`replace`); its bbox is non-empty.
  Pipeline validation is caught in an error scope and rejects `read()` (`VDB_UNSUPPORTED_DEVICE`).
- Deviation from the brief's literal signature `gridStats(device, pool, gridId, encoder?)`: the encoder sits in the
  options object (`{ encoder, histogramBins }`), the same shape as `decodeToAtlas`.
- The range no longer needs a GPU pre-pass: `pool.info(id).rootMin/rootMax` are the same f32s v1 read on the GPU, so
  each tool is one dispatch.

### Kernels

One shader per (kernel, grid type): `vdbModuleWgsl({ slot: { group: 0, firstBinding: 0 }, types: [type], profile:
'sample' })` + a footer calling only `vdbAccessorInit`, `vdbIsActive`, `vdbReadValue`, `vdbSample`. Group 0 = pool
(`vdbModuleEntries`, compute visibility) + a 80 B uniform; group 1 = outputs. Default module options, so
`pnpm wgsl:size` is unchanged (156 variants). Dispatch is v1's: `4x4x4` workgroups over the dense index bbox
(stats) or the output dims (atlas). Both stats paths are kept (atomics when root min ≥ 0; dump + CPU reduce
otherwise), as are v1's fixed-point mean and histogram binning.

## Parity evidence

All on this Mac, headless shell 1243, SwiftShader ("google swiftshader"), port 5402.

1. **v1 vs core, bit for bit (one-off harness, not committed).** v1 `compute.ts` (saved before the rewrite) and the
   new core ran side by side on 7 grids (box/sphere/torus Float, sphere/box Fp8, torus FpN, and a dense Float grid
   with negative values for the dump path), 79 comparisons: `gridStats` at 256 and 37 bins (min, max, mean,
   count, every bin, fast-path choice), `decodeToAtlas` in 7 option sets (default; nearest; maxDim 40 float32;
   maxDim 96 raw; `normalize: false`; explicit range; nearest float32 maxDim 64), and `valueTransform` with
   all four presets on the 4 Float grids against `applyValueTransform`. **79 / 79 identical** (`Object.is` on every
   value, byte-identical images), no uncaptured errors.
2. **Core vs CPU twins (`e2e/compute.spec.ts`, committed).** 5 grids in one pool started at 4 KiB, after a filler grid
   (non-zero ids and offsets); half the calls record into a host encoder with the pool update, half self-submit.
   `gridStats`: count, min, max exact; histogram L1 0 and mean |Δ| 0 on all 5 (both paths). `decodeToAtlas`: 25 runs,
   **11,126,200 / 11,126,200 raw values bit-exact** vs `decodeToAtlasCpu`, formatted outputs identical. Value
   transform round trip: leaf values doubled / tiles unchanged on 4,000 samples, `version` unchanged (in-place
   replace), GPU nearest atlas of the replaced grid 202,581 / 202,581 exact, stats max exact. The spec requires bit
   exactness only on SwiftShader; elsewhere: histogram L1 ≤ max(2, 1e-4·count), mean |Δ| < 1e-5, raw |Δ| < 1e-5, uint8
   ±1.
3. **Node.** `test/core/compute.test.ts` (fake device): validation before device work, dispatch shapes, pool bound
   at slot 0, one submit when self-submitting and none with a host encoder, the tool frees exactly its own buffers
   (never the pool's), `read()` idempotent, `dispose()` → `VDB_DISPOSED`. `test/tools/cpu-compute.test.ts`: the
   twins against independent references (f64 scan, sidecar counts, `sampleTrilinear`, leaf/tile split).

## Demos

- **Demo 04**: device-first, one `VDBGridPool`, `gridStats` / `valueTransform` / `decodeToAtlas` through the three
  wrappers; checks against `gridStatsCpu` and the sidecar; the transform check now uses `getDim` (leaf vs tile) on
  the CPU instead of v1's ad hoc GPU level probe, plus a GPU `gridStats` of the replaced grid. **K2.5:** the atlas
  is sampled through the wrapper's stock `Data3DTexture` + `texture3D()`. It works on headless SwiftShader now
  (three r187), and renders the existing golden **bit for bit** (0 / 307,200 pixels differ; a sanity mutation of the
  `uvw` in the 3D path changes 42,356 pixels, so the path is really used). The storage-buffer workaround is
  deleted rather than kept behind a flag; `e2e/demo-04.spec.ts` drops `texture=storage` and asserts
  `textureMode: "3d"`. Presentation default flipped to the canvas (`?presentation=readback` opt-in, which the e2e
  already passes). Golden unchanged.
- **Demo 06**: device-first renderer, a `VDBGridPool` holding the loaded grid (`replace` on reload), histogram from
  the core `gridStats` via the wrapper; state gains `histogramFrom: "gpu" | "cpu"` and both e2e tests require
  `"gpu"`. The volume still renders with the v1 `NanoVDBVolumeMaterial` (part A's port replaces it):
  `makeVolumeMaterial(grid)` is the one call to switch. Its CPU panels still use `NanoVDBGrid`'s metadata helpers.
  nvdb golden: **7,999 px, ratio 0.03**, identical to the pre-port run (and pixel-identical to the pre-port
  screenshot), the known cross-OS failure.

Full e2e: 16 passed, 1 failed (demo-06 nvdb golden, 0.03, known). No snapshot changed.
