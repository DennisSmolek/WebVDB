# K2 handoff: the three.js adapter on the engine-free core

## K2.1/K2.2

`getDevice(renderer)`, `getGPUTexture(renderer, texture)`, `VDBGridNode` and the `vdbSample` / `vdbReadValue` TSL
helpers, per [docs/design/K1-core.md](../design/K1-core.md) §6, on three r187 (D23). The v1 material, compute
utilities and sequence player are untouched and still exported (K2.3 ports them).

### API

```ts
const device = await adapter.requestDevice({ requiredLimits: VDBGridPool.requiredLimits(adapter) });
const renderer = new WebGPURenderer({ device });        // pass the device to keep the pool alive past renderer.dispose()
await renderer.init();
const pool = await VDBGridPool.create(getDevice(renderer));
const id = pool.add(image, { transform });
pool.flush();

const grids = new VDBGridNode(renderer, pool, { profile: 'sample' }); // types default to [...pool.types] (checked)
const d = vdbSample(grids, id, positionWorld);                        // TSL float node; { space: 'index' } for index space
const v = vdbReadValue(grids, gridIdNode, ivec3(...));               // any profile
// or WGSL: wgslFn(`fn f(g: u32, p: vec3f) -> f32 { var a = vdbAccessorInit(g); return vdbSample(&a, p); }`, [grids.module])
// per frame, after the pool's update was submitted:
grids.update();                                                       // true when it rebound
```

- `getDevice(renderer)` / `getGPUTexture(renderer, tex)`: the upscaler/denoiser semantics (throw, don't return
  undefined). Errors are `VDBError`: `VDB_UNSUPPORTED_DEVICE` "three adapter: getDevice requires an initialized
  WebGPURenderer (await renderer.init()) on its WebGPU backend; …", `VDB_BAD_OPTION` for an unallocated texture.
  `ThreeRendererLike` is `{ backend: object }`: `@types/three` r187's `Backend` doesn't declare `get`, so the
  downsampler's `{ backend: { get … } }` shape rejects a real `WebGPURenderer` at compile time here. The
  internals are checked at runtime instead.
- `new VDBGridNode(renderer, pool, { types?, profile?, sampler?, isActive?, outside?, name? })`: `profile`
  defaults to `'sample'`; `majorant` is refused (D22); `slot`/`buffer` are refused (three owns the binding);
  unknown keys are refused. `types` omitted = `[...pool.types]` (throws if the pool is empty); given = the
  caller's choice (a pool may be shared by modules compiling different subsets), and `grids.check()` runs
  `checkModule`. The layout version is checked either way. The pool must live on the renderer's device.
- Members: `storage` (the storage node), `module` (the code node), `options` (normalized), `name`, `version`,
  `update()`, `check()`, `dispose()`.
- `vdbSample(grids, gridIndex, position, { space: 'world' | 'index' })`: world goes through the record's
  `vdbWorldToIndex` (so `setTransform` instances work); needs `sample`+. `vdbReadValue(grids, gridIndex, ijk)`.
  `gridIndex` is a `uint` node or a non-negative integer. Each helper is one `wgslFn` (`vdbThreeSampleWorld`,
  `vdbThreeSampleIndex`, `vdbThreeReadValue`) made once per `VDBGridNode`, including `grids.module`; three emits
  the module once per shader however many helpers a shader calls (the e2e kernel calls all three).

### How the binding works on r187 (internals touched)

| Internal | Use | Checked |
|---|---|---|
| `renderer.backend.isWebGPUBackend`, `.device` | `getDevice`, and the pool/renderer device match | at every call |
| `renderer.backend.get(obj)` | `.texture` for `getGPUTexture`; `.buffer = pool.buffer` on each stand-in before three sees it (`WebGPUAttributeUtils.createAttribute` creates a buffer only when it is undefined) | `update()`: for every stand-in three used, `.buffer` is still the pool's and the record holds no other `GPUBuffer`; else a loud `VDB_UNSUPPORTED_DEVICE` naming three r<REVISION> and the r187 peer range |
| `renderer.backend.destroyAttribute` | wrapped once per backend: for a stand-in, a 16 B throwaway replaces the pool's buffer before three's `destroy()` | exists, at construction |
| `renderer._attributes.has(attr)` | "three used this stand-in" for the check above | exists, at construction |
| `Bindings` rebuilds a storage bind group when `NodeStorageBuffer.attribute` (the storage node's `value`) changes | rebind = `storage.value = newStandIn` | e2e: growth, no new shader module or pipeline, reads correct |
| `Node._getChildren` finds node-valued own properties | the module `CodeNode` holds the storage node as `vdbPool`, so any shader including the module emits the binding | e2e |
| `storageNode.build(builder, 'property')` → `WGSLNodeBuilder.getPropertyName` → `<name>.value` | the module's buffer reference | e2e asserts the ref is exactly `vdbPool.value` |
| `builder.getCodeFromNode(node, type).code = text` | emit the module text at module scope (bvh's pattern) | e2e |

Disposal: `retire(attr)` = `attr.dispose()` → `Attributes.delete` → wrapped `destroyAttribute` → throwaway
destroyed. Happens on rebind (old stand-in), `grids.dispose()`, and `renderer.dispose()` (`Attributes.dispose`).
Trap: a renderer built **without** `{ device }` destroys its own device in `renderer.dispose()`
(`WebGPUBackend.dispose`, `parameters.device === undefined`), and the pool's buffer with it. That isn't fixable
in the adapter; it is documented in `device.ts` and CLAUDE.md.

### Evidence

- `pnpm typecheck`, `pnpm build`: clean. `pnpm test`: 46 files, **848 passed** / 7 skipped (+8 new).
- `e2e/three-grid-node.spec.ts` (headless shell 1243, SwiftShader "google / swiftshader", port 5397): **pass**, ~3 s.
  - Phase 1: pool from 4 KiB holding box Float, sphere Fp8, torus FpN, and sphere Float again with a
    rotation (30° about (1,1,0)) + scale 0.5 + translation instance transform. One TSL compute node,
    4,672 probes, per-probe grid id: `vdbReadValue` (256 per grid), `vdbSample` index space (256), world
    space (256), plus padding probes on dead id 99 (all read exactly 0).
  - Phase 2: two more grids (torus Float, box FpN) force a growth (version 1 → 2); `update()` returned true;
    **0 new shader modules, 0 new compute pipelines**; all six grids re-probed, twice (once more after two
    extra `flush()`es retire the pre-growth buffer).
  - Parity (phase 2, 4,608 probes): every probe within 1e-5 (read) / 1e-3 (trilinear) of the f64 twins
    (`readValue`, `sampleTrilinear`, world points through `info().worldToIndex` in f64); **max |Δ| 7.2e-7**
    (the transformed instance, world space: f32 record affine vs f64). 4,513 / 4,608 bit-exact against the
    f64 twins. Against f32 twins (`readValueF32`; trilinear = f32 taps + `a + t·(b − a)` lerps) **read and
    index-space samples are bit-exact on all 6 grids (3,072 / 3,072)**, and the spec gates that on SwiftShader
    only (WGSL leaves `mix` and FMA to the implementation). World-space samples have no f32 twin of the
    affine.
  - Phase 3: `await renderer.dispose()`; the destroy guard made ≥ 2 throwaways; raw WebGPU readback of
    `pool.buffer`: all 6 image ranges byte-identical, no validation error; then `remove` + `replace` +
    `flush` and a second readback: still identical, `lastError` null. No uncaptured errors in any phase.
  - Fail-before checks (mutations, reverted): disabling the destroy guard fails phase 3 with "Buffer
    'three grid node (v2)' used in submit while destroyed"; making `update()` never rebind fails phase 2.
- Full e2e: 13 passed, 1 failed: demo-06 nvdb golden (7,999 px, 0.03), the known cross-OS failure, identical to
  K2.0. No snapshot changed.

### Friction in the core API

1. `checkModule(pool, options)` validates the whole option set, so a caller that only wants the type/layout
   check must pass a dummy binding (`buffer: 'x.value'`). A `checkTypes(pool, types)` or making the binding
   optional there would be cleaner.
2. No error code for "the engine's internals are not what the adapter expects"; reused
   `VDB_UNSUPPORTED_DEVICE`. A `VDB_UNSUPPORTED_ENGINE` code would be more honest (core change, so not done).
3. `pool.info(id)` exposes the f64 affines only. World-space parity can't be bit-exact without the f32 record
   values; `decodeRecord` has them but needs a readback. An `info().worldToIndexF32` (or a `tools` twin of
   `vdbWorldToIndex`) would make it exact.
4. Pool types start empty, so "types default to the pool's" only works after the first `add`. Fine, but
   K2.3's material constructor will want explicit types (or must be built after loading).
5. No GPU write path into a pool image. v1's `valueTransform` mutates the grid buffer in place
   (`read_write`); the pool binds read-only and keeps no CPU copy, and `replace` takes a CPU `Uint32Array`.
   See K2.3 risk 2.

### K2.3 plan (port material / compute / sequence onto the core)

1. **Material** (`NanoVDBVolumeMaterial` → built on `VDBGridNode`). Constructor takes `(renderer, grids:
   VDBGridNode, gridId | gridIdNode, params)` instead of `{ grid, pnanovdbSource }`. Replace `assembleVolumeWgsl`
   with one entry `wgslFn` (`[grids.module]` as include) whose body is today's march, retargeted to the public
   API: `vdbWorldToIndex/Dir(g, …)`, `vdbRayClip(g, o, d, &t)` (note K1.4b open issue 2: it clips to
   `[min, max + 1]`; trilinear support starts at `min − 1`, so pad the min side to keep v1 pixels),
   `vdbSample(&acc, p)` with two accessors (primary + shadow). The `ptr<storage>` parameter and
   `arrayLength` go away (the module's node property emits the binding). `rebindGrid` becomes `gridId`
   uniform + `pool.replace`; `maxGridBytes` disappears (pool growth + `grids.update()`). Helpers
   (`nvdbx_hg_phase`, `nvdbx_hash12`) need a home: a second `CodeNode` include (fine: different names) or
   inline in the entry. Gate: demo 02/05/07 goldens unchanged (re-baseline only with a DIVERGES row, K2.4).
   *Risk:* v1 reads the NanoVDB map in the shader (`grid_world_to_indexf`); the pool uses the record's f32
   affine composed in f64. Should match to ~1e-7 relative; goldens are the check. Per-pixel cost: `vdbSample`
   adds the `ok` branch and the accessor copy-in/out (K1.4a "no sub-object pointers"); measure on hardware.
2. **Compute** (`gridStats`, `valueTransform`, `decodeToAtlas`). These are raw WebGPU and don't need three:
   port them onto the core's `slot` mode (`vdbModuleWgsl({ slot, types, profile: 'sample' })` +
   `pool.bindGroupEntry(slot)`), taking `(device | renderer, pool, id)`; keep thin three wrappers that call
   `getDevice(renderer)` (and `getGPUTexture` for the atlas). Generated modules are read-only, so:
   `gridStats` and `decodeToAtlas` port directly. **`valueTransform` can't mutate the pool in place**: either
   (a) GPU: write the transformed values into a scratch copy of the image (copyBufferToBuffer the range, then
   a kernel with its own `read_write` binding on the scratch), then a new core `pool.replaceFromBuffer(id,
   buffer, offset)` that copies GPU→pool in `update`; or (b) CPU via `tools` (`transform`) + `pool.replace`.
   *Recommendation:* (b) for 0.1 (no core API change, CPU twin already exists), (a) as a follow-up if demo 04
   needs interactive speed. Owner decides; test: demo 04 timing on the reference device.
3. **Sequence** (`NanoVDBSequence`). Frames become `pool.replace(id, frame)`; reserve
   `pool.add(first, { capacity: maxFrameBytes })` so replaces stay in place (no `version` change, no
   rebind). A larger frame without capacity moves the image; the next `update` may grow (version bump) and the
   player must call `grids.update()` after `pool.update`. Contract to document: submit each `update`'s encoder
   before the second `update` after it (K1 pool lifecycle). *Risk:* `replace` holds the frame `Uint32Array` by
   reference until `settled()`; a player that recycles frame buffers must not reuse one before that.
4. **Order:** sequence first (smallest, proves `replace` + rebind on demo 07), then material (goldens), then
   compute. Delete `wgsl.ts` (`rewriteBufferGlobal`, `assembleVolumeWgsl`) and `NanoVDBGrid.storageAttribute`
   when the last v1 user is gone; keep `NanoVDBGrid`'s CPU metadata helpers or move them to `pool.info()`.
5. **Open three-side risks:** two `VDBGridNode`s in one shader redeclare the module (Trap: one module per shader);
   a material and a compute kernel sharing one pool should share one `VDBGridNode` (one stand-in, one rebind).
   Fragment-stage storage buffers on compatibility-mode devices (§6 item 4) are untested.
