## What the example shows (the engine contract, D8)

1. **The host owns the device.** It calls `requestDevice({ requiredLimits: VDBGridPool.requiredLimits(adapter) })`,
   and the core only ever receives that device.
2. **One module, one pool, many grids.** It calls `vdbModuleWgsl({ slot: { group: 0, firstBinding: 0 }, types:
   ['float', 'fp8'], profile: 'march' })`. The host puts `vdbModuleEntries({ slot, visibility: FRAGMENT })` into
   its own bind group layout next to its uniforms at binding 1. It calls `checkModule(pool, options)` after each
   `add`.
3. **The core records into the host's encoder.** Each frame calls `pool.update(encoder)` before the pass that reads
   the pool, then submits that encoder at once, so it is always submitted before the next update.
4. **Version contract.** The bind group is rebuilt when `pool.version !== boundVersion`, checked after `update`. The
   first frame grows the 1 MiB pool to fit the smoke (version 1). The button adds the torus
   (`torus_fog_fp8.nvdb`, with an instance transform), and the next update grows the pool to 13.4 MiB (version 2).
   The bind group is then rebuilt, for 2 builds in total.
5. **Transform contract.** "Spin it" calls `pool.setTransform` every frame. `revision` goes up by one per frame,
   `version` stays the same, and the bind group is not rebuilt (measured: revision 2→14 over 12 frames, version 2,
   2 builds).
6. **`await pool.settled()`** after each growing frame. `pool.lastError` is shown in the panel if it is set.
7. **Teardown** on `pagehide`: wait for `onSubmittedWorkDone`, then `pool.dispose()`, then free the host's own
   resources. The host also destroys the device because it created it.

Rendering: the world ray goes into each grid's index space (`vdbWorldToIndex{,Dir}`), is clipped with
`vdbRayClip`, and the grids are sorted front to back by entry `t`. The placement keeps them from overlapping, so
compositing them in that order is exact. Inside a grid, `vdbHddaInit/Step` walks 8³ cells. A cell is skipped when
its bound is 0. The bound is the max of `vdbNodeMax(cell + 8·{0,1}³, 8)`, the 2x2x2 support from the Traps, because
trilinear taps reach into the +x/+y/+z neighbours. Kept cells are sampled with `vdbSample` at 1 voxel per step, on a
fixed lattice in `t`. There is no lighting, only emission-absorption.

**Skip check:** forcing every cell to "keep" (`if true`) changes 25 of 307,200 pixels at Playwright `threshold: 0`
on the smoke golden. Those are small float differences in the lattice arithmetic; the image is otherwise the same.

## API friction (first real consumer; feedback for the owner)

Each item has a suggestion, pros and cons, and the test that would settle it.

1. **Types must be known up front.** `pool.types` reflects only the grids present now, but the shader is built once.
   A host that adds an Fp8 grid later has to either compile `fp8` from the start (this demo does: +2.3 KB min, 28,501 → 30,830 B) or
   rebuild its pipeline. `checkModule` catches a mismatch, but only after the `add`.
   *Suggestion:* document the "compile what you will add" pattern in the core README, and have `checkModule`'s
   message mention rebuilding the pipeline. *Pro:* no API change. *Con:* some hosts will still pay for a recompile
   at runtime. *Test:* none needed; this is docs.
2. **`vdbModuleEntries` defaults `visibility` to COMPUTE.** A render host that forgets the option gets a
   pipeline-layout validation error. *Suggestion:* make `visibility` required, or default to
   `COMPUTE | FRAGMENT` (read-only storage is legal in both). *Pro:* removes a foot-gun. *Con:* changes a default
   that K1.4a chose to match bvh. *Test:* a unit test that the default covers FRAGMENT; this demo
   then works without the option.
3. **No trilinear-safe skip bound.** Every march consumer has to rediscover that `vdbNodeMax` at the cell does not
   bound a trilinear sample, and write the 8-query 2x2x2 loop themselves. *Suggestion:* add a `march` helper,
   e.g. `vdbCellBoundTrilinear(acc, cell, dim) -> f32`, with a CPU twin in `tools/cpu/march.ts` (the twin of the
   dilated bound already exists in its tests). *Pro:* it is correct by default. *Con:* +~300 B per `march` module;
   FpN has only 7 B of KiB headroom (K1.4b), so the budget would have to move. *Test:* the K1.4b property test
   (every trilinear sample ≤ its cell's dilated bound), run through the GPU probe.
4. **The HDDA exit `t` is not public.** The cell's exit is `min(h.next.x, h.next.y, h.next.z, h.tmax)`, but those
   fields come through `alias VdbHdda = vdb_hdda_t` and are vendored names, not documented API. *Suggestion:* add
   `vdbHddaCellEnd(&h) -> f32` (and perhaps `vdbHddaCell(&h) -> vec3i`), or document the fields as stable.
   *Pro:* consumers don't depend on vendored field names. *Con:* one more wrapper. *Test:* the existing
   `hddaWalk` twin already emits `t1 = min(next, tmax)`.
5. **The bind group order is easy to get wrong** (see the Trap). If a host builds its bind group before `update`,
   it renders with the old buffer, which is alive but stale. It gets no error, just missing grids for one frame (or
   forever, if it caches by a version read before `update`). *Suggestion:* say "check `version` after `update`" in
   the `update` and `version` doc comments. *Test:* a fake-GPU unit test is possible, but this is a docs fix.
6. **`slot` is optional in `VDBModuleOptions`**, so a host that keeps one options object needs `options.slot!` to
   call `vdbModuleEntries` and `bindGroupEntry`. The shapes also differ: `vdbModuleEntries({ slot })` versus
   `bindGroupEntry(slot)`. This is minor. *Suggestion:* leave it, or accept the module options object in both.
7. **`vdbRayClip` clips to `[min, max + 1]`**, which cuts off the min-side half of the trilinear support
   (K1.4b open issue 2). The demo doesn't pad. For fog volumes with empty borders this is invisible.

What worked well: `pool.info(id).worldBBox` is valid right after `add`, before any upload, which made camera
framing trivial. `add` returning the id at once and `update` doing everything inside the host's encoder made
the frame loop short. `settled()` and `lastError` were easy to fit in. The pool and generator errors that came
up were clear.

### API changes (before → after)

| Item | Before | After |
|---|---|---|
| 2. `vdbModuleEntries` visibility | default `COMPUTE` (0x4) | default `COMPUTE \| FRAGMENT` (0x6, numeric so Node tests work); an explicit `visibility` still overrides |
| 6. Slot shape | `vdbModuleEntries({ slot, visibility? })` only; `VDBModuleOptions.slot` optional, so hosts wrote `options.slot!` | `vdbModuleEntries(slot \| { slot, visibility? })`; `VDBModuleOptions = VDBSlotModuleOptions \| VDBBufferModuleOptions` (`{ slot: VDBSlot; buffer?: undefined }` / `{ buffer: string; slot?: undefined }`). Annotating `VDBSlotModuleOptions` gives `options.slot: VDBSlot`. `pool.bindGroupEntry(slot)` takes the same `VDBSlot` (unchanged). A bare `{ group, firstBinding }` is now accepted by `vdbModuleEntries` (it was rejected as "positional"); `{ group, firstBinding, visibility }` is rejected. `vdbModuleWgsl` still rejects a top-level `group`/`firstBinding`. |
| 3. Trilinear-safe bound | each host hand-writes the 2x2x2 `vdbNodeMax` loop | `helpers: ['cellBoundTrilinear']` (`march`) → `vdbCellBoundTrilinear(acc, ijk, dim) -> f32`; twin `tools` `cellBoundTrilinear` |
| 4. HDDA exit `t` | `min(h.next.x, h.next.y, h.next.z, h.tmax)` on vendored fields | `helpers: ['hddaCellEnd']` (`march`) → `vdbHddaCellEnd(&h) -> f32`; twin `tools` `hddaCellEnd` (`hddaWalk` now uses it for `t1`) |
| 7. Min-side clip | `vdbRayClip` clips to `[min, max + 1]` | unchanged; new sibling `helpers: ['rayClipSupport']` (`sample`+) → `vdbRayClipSupport(g, o, d, &t)`, clips to the sampler's support: `[min - 1, max + 1]` trilinear, `[min - 0.5, max + 0.5]` nearest. Twin `tools` `rayClipSupport(img, o, d, t, { sampler })`. A sibling rather than a `vdbRayClip` option because API functions are always emitted (the generator prunes only vendored chunks); `helpers` keeps default bytes unchanged. |
| 1. Types up front | docs only in the handoff | `VDB_ALL_SCALAR_TYPES` (frozen, = `VDB_GRID_TYPE_NAMES`); JSDoc on `vdbModuleWgsl`, `VDBModuleCommonOptions.types`, `VDBGridPool.add` and `.types`; the `VDB_TYPE_NOT_COMPILED` message now says "A module must be generated for every type the host may add: regenerate it with types that include … (e.g. [...pool.types], or VDB_ALL_SCALAR_TYPES to never rebuild) and rebuild the pipeline that uses it." No pool-side type declaration API. |
| 5. Bind group order | Trap in CLAUDE.md only | JSDoc on `update`, `bindGroupEntry` and `version`: call `update(encoder)` before building or reusing bind groups this frame; a bind group built before `update()` keeps the previous (still-alive) buffer and silently misses new grids. |
| (coordinator, from K2.2) `checkModule` | full module options only | also `checkModule(poolLike, { types, layoutVersion? })` (`VDBModuleTypeCheck`), a type/layout-only check; `layoutVersion` defaults to `VDB_GPU_LAYOUT_VERSION`. The full form is unchanged. The layout message now says "the module targets layout N". |
| (coordinator, from K2.2) error code | — | `VDB_ENGINE_MISMATCH` in `VDBErrorCode`: an engine adapter finds the engine's internals don't behave as it expects. `src/three` not touched. |

`helpers` is a set (order and duplicates don't matter), validated: unknown names and a helper below its
profile throw `VDB_BAD_OPTION` (e.g. "helper 'hddaCellEnd' needs profile 'march' or above"). New exported types:
`VDBModuleHelper`, `VDBModuleCommonOptions`, `VDBSlotModuleOptions`, `VDBBufferModuleOptions`, `VDBModuleTypeCheck`.

Buffer mode is unchanged: `{ buffer: 'vdbPool.value', types, profile }` generates the same bytes. **What
`VDBGridNode` (K2.2) may need to absorb:** (a) code that reads `options.slot`/`options.buffer` off a
`VDBModuleOptions` still compiles (both members declare both keys); an object literal with both `slot` and
`buffer` set, or a variable typed as the old interface with an optional `slot`, is now a type error. (b) If it
calls `vdbModuleEntries({ group, firstBinding })` expecting a throw, that now succeeds. (c) If it relies on the
default visibility being COMPUTE only, it now includes FRAGMENT. (d) It can drop the dummy binding in its
`checkModule` call and pass `{ types }`. (e) Switch its reuse of `VDB_UNSUPPORTED_DEVICE` to
`VDB_ENGINE_MISMATCH`.
