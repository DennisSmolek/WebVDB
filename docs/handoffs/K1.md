### For the WGSL generator (K1.4a)

Import `vdbPoolLayoutWgsl()` from `core/pool/layout.ts` and prepend its text; don't restate numbers. It emits
`u32` consts: `VDB_GPU_LAYOUT_VERSION`, `VDB_POOL_MAGIC`, `VDB_POOL_ALIGN`, `VDB_POOL_TABLE_OFFSET` (32, bytes),
`VDB_POOL_TABLE_WORD` (8), `VDB_POOL_RECORD_BYTES` (160), `VDB_POOL_RECORD_WORDS` (40), `VDB_HEADER_<FIELD>`
(word index; `VDB_HEADER_GRID_COUNT = 3u`), `VDB_REC_<FIELD>` (word within a record), `VDB_REC_FLAG_<NAME>`,
`VDB_REC_GRID_CLASS_SHIFT` (8), `VDB_REC_BRICK_LOG2_SHIFT` (16), `VDB_REC_BYTE_FIELD_MASK` (0xff).
Word `w` of grid `g` = `vdb_load(VDB_POOL_TABLE_WORD + g * VDB_POOL_RECORD_WORDS + w)`.

Record words: 0 imageOffset (bytes, 32-aligned; `vdb_make_buffer(imageOffset, …)`), 1 imageBytes, 2 gridType,
3 flags (b0 live, b1 hasStats, b2 hasBrickMajorant, b3 instanceTransform, b8–15 class, b16–23 brick log2), 4–15
worldToIndex (f32 3x4 row-major), 16–27 indexToWorld, 28–30 indexBBoxMin (i32), 31 background (f32), 32–34
indexBBoxMax (i32, inclusive), 35 valueMax (f32), 36 majorantOffset (bytes; 0 = none), 37–39 majorantDims.
A dead record is all zeros.

### Deviations from the note

- **Host-buffer mode never re-lays out.** Placement is checked at `add`/`replace`/`setMajorant`, which throw
  `VDB_POOL_FULL` synchronously with the pool unchanged; the table capacity is `maxGrids`, fixed. Compacting
  inside one buffer would read ranges that same-update queue writes may already have overwritten.
- **`replace` drops the grid's brick majorant** (it described the old image; a stale bound biases tracking).
  Transform, label and caller `valueMax` are kept. Call `setMajorant` after `replace`.
- **`setTransform` also changes record word 3** (flag b3), not only words 4–27.
- **`valueMax` without `HasMinMax`** (and no caller bound) is `+Infinity`, not the root max (garbage without
  stats). See open issue 1.
- **`revision` bumps at the staging call**, not at `update`.
- Extra file `affine.ts`; extra public getters `gridCapacity`, `gridCount`; `info()` also returns the f64 affines.
- Negated zero translations are written as +0 so record bits are stable.

### Open issues

1. `valueMax = +Infinity` for stats-less grids is a correct bound but useless for delta tracking; K1.4b's
   majorant code should treat a non-finite bound as "needs `valueMax` or a brick majorant" and say so.
2. Growth on a table shortfall doubles the bytes too (`max(needed, 2 × current)`, as the note says) even when
   only the table is full; cheap to change if it matters.
3. `unsupportedReason` knows a device is lost only after the core has seen it (`create` watches `device.lost`).
   Compatibility-mode fragment limits (§6 item 4) are not checked: the pool itself is usable from compute.
4. `create` uses an `out-of-memory` error scope for the first buffer only; growth in `update` is synchronous and
   can't await one.
5. Records to add when K1 lands (§10): DIVERGES row for the f32 record affines composed in f64.

## Integration

K1.3 (pool) and K1.4a (generator) joined; not committed at hand-off.

- **One shared module, `core/types.ts`:** `VDBGridTypeName`, `VDB_GRID_TYPE_IDS`, `VDB_GRID_TYPE_NAMES`, `VDBSlot`. `pool/image-header.ts`, `pool/pool.ts`, `wgsl/api.ts`, `wgsl/generate.ts` and `wgsl/types.ts` import from it; `core/index.ts` exports each once. `VDBSlot` is `readonly` now (the pool's copy was mutable; mutable values still assign). `test/core/types.test.ts` checks the id table against `PNanoVDB.h`, `stride-tables.json`, the vendored WGSL constants, and `tools` (`gridTypeIds`, `bytes.GRID_TYPE_*`).
- **Layout seam closed:** `core/wgsl/record-constants.ts` is deleted. `generate.ts` takes `vdbPoolLayoutWgsl()` from `core/pool/layout.ts` and keeps only the `const` lines the module body references (same pruning as before; layout.ts stays the one source). The one name that differed: the API layer now uses `VDB_HEADER_GRID_COUNT` (layout.ts's name), not `VDB_POOL_HEADER_GRID_COUNT`. The old temporary `VDB_POOL_LAYOUT_VERSION` const was never referenced and is gone; `VDB_GPU_LAYOUT_VERSION` exists in WGSL only if a module references it (none does).
- **Byte delta:** every one of the 72 variants is 8 raw bytes smaller (the shorter header-count name); the pruning keeps the constant block the same size as before. Example, `read/float/slot`: 21,094 -> 21,086 raw (before minification, §3.5 sizes shift by the same 8 B at most).
- **`checkModule`** compares `layoutVersion` to `VDB_GPU_LAYOUT_VERSION` from `layout.ts`, and a real `VDBGridPool` passes as `VDBModulePoolLike` without a cast. Tests (`wgsl-generate.test.ts`): a pool holding float + fp8 passes for the exact and a wider set and throws `VDB_TYPE_NOT_COMPILED` (naming `fp8`) for `types: ['float']`; the layout version test uses layout.ts's constant; a test asserts every emitted layout const line is verbatim a line of `vdbPoolLayoutWgsl()` and that the names the API layers use are emitted.
- `VDB_GPU_LAYOUT_VERSION` is exported only from `core/pool/layout.ts` via `core/index.ts`.
- Gates: `pnpm typecheck`, `pnpm build` clean; `pnpm test` 447 passed (440 + 7); WGSL compile matrix 72/72; `e2e/pool-readback.spec.ts` green (`WEBVDB_E2E_PORT=5392`); `extract-wgsl-chunks.mjs` leaves no diff.
