### For the WGSL generator (K1.4a)

Import `vdbPoolLayoutWgsl()` from `core/pool/layout.ts` and prepend its text; don't restate numbers. It emits
`u32` consts: `VDB_GPU_LAYOUT_VERSION`, `VDB_POOL_MAGIC`, `VDB_POOL_ALIGN`, `VDB_POOL_TABLE_OFFSET` (32, bytes),
`VDB_POOL_TABLE_WORD` (8), `VDB_POOL_RECORD_BYTES` (160), `VDB_POOL_RECORD_WORDS` (40), `VDB_HEADER_<FIELD>`
(word index; `VDB_HEADER_GRID_COUNT = 3u`), `VDB_REC_<FIELD>` (word within a record), `VDB_REC_FLAG_<NAME>`,
`VDB_REC_GRID_CLASS_SHIFT` (8), `VDB_REC_BRICK_LOG2_SHIFT` (16), `VDB_REC_BYTE_FIELD_MASK` (0xff).
Word `w` of grid `g` = `vdb_load(VDB_POOL_TABLE_WORD + g * VDB_POOL_RECORD_WORDS + w)`.

Record words: 0 imageOffset (bytes, 32-aligned; `vdb_make_buffer(imageOffset, …)`), 1 imageBytes, 2 gridType,
3 flags (b0 live, b1 hasStats, b2 hasBrickMajorant, b3 instanceTransform, b8–15 class, b16–23 brick log2), 4–15
worldToIndex (f32 3x4 row-major), 16–27 indexToWorld, 28–30 indexBBoxMin (i32), 31 background (f32), 32–34
indexBBoxMax (i32, inclusive), 35 valueMax (f32), 36 majorantOffset (bytes; 0 = none), 37–39 majorantDims.
A dead record is all zeros.

### Deviations from the note

- **Host-buffer mode never re-lays out.** Placement is checked at `add`/`replace`/`setMajorant`, which throw
  `VDB_POOL_FULL` synchronously with the pool unchanged; the table capacity is `maxGrids`, fixed. Compacting
  inside one buffer would read ranges that same-update queue writes may already have overwritten.
- **`replace` drops the grid's brick majorant** (it described the old image; a stale bound biases tracking).
  Transform, label and caller `valueMax` are kept. Call `setMajorant` after `replace`.
- **`setTransform` also changes record word 3** (flag b3), not only words 4–27.
- **`valueMax` without `HasMinMax`** (and no caller bound) is `+Infinity`, not the root max (garbage without
  stats). See open issue 1.
- **`revision` bumps at the staging call**, not at `update`.
- Extra file `affine.ts`; extra public getters `gridCapacity`, `gridCount`; `info()` also returns the f64 affines.
- Negated zero translations are written as +0 so record bits are stable.

### Open issues

1. `valueMax = +Infinity` for stats-less grids is a correct bound but useless for delta tracking; K1.4b's
   majorant code should treat a non-finite bound as "needs `valueMax` or a brick majorant" and say so.
2. Growth on a table shortfall doubles the bytes too (`max(needed, 2 × current)`, as the note says) even when
   only the table is full; cheap to change if it matters.
3. `unsupportedReason` knows a device is lost only after the core has seen it (`create` watches `device.lost`).
   Compatibility-mode fragment limits (§6 item 4) are not checked: the pool itself is usable from compute.
4. `create` uses an `out-of-memory` error scope for the first buffer only; growth in `update` is synchronous and
   can't await one.
5. Records to add when K1 lands (§10): DIVERGES row for the f32 record affines composed in f64.

- `VDB_GPU_LAYOUT_VERSION` is exported only from `core/pool/layout.ts` via `core/index.ts`.
- Gates: `pnpm typecheck`, `pnpm build` clean; `pnpm test` 447 passed (440 + 7); WGSL compile matrix 72/72; `e2e/pool-readback.spec.ts` green (`WEBVDB_E2E_PORT=5392`); `extract-wgsl-chunks.mjs` leaves no diff.

## K1.3 pool lifecycle fixes

Three lifecycle bugs from an independent review, fixed in `core/pool/pool.ts`. Tests in
`test/core/pool-lifecycle.test.ts` (10 new); `fake-gpu.ts` now models error scopes, failed allocations
(`failCreate`, invalid buffers), `onSubmittedWorkDone` (`completeWork()`), and delayed scope results
(`holdScopes()`). Three `pool.test.ts` cases changed to the new behaviour (below).

### 1. Requests that can never fit throw at staging

`add`, `replace` (when it moves) and `setMajorant` (when it moves) throw `VDB_POOL_LIMIT` synchronously, with
the pool unchanged, when `dataStartOffset(capacity) + align32(bytes...) > limit`. `capacity` is the table size
the request needs (the current capacity doubled until it holds the id). An image and its majorant are checked
together (`add` with `majorant`, `setMajorant`). Before, such a range was staged, and every later `update`
threw, so in-place `replace`s of other grids never reached the GPU.

Grids that each fit but not together still fail in `update`. Now `update` doesn't re-lay out, but still writes
every range placed in the current buffer (in-place replaces, placements made at staging), the dirty records and
the header. Then it throws `VDB_POOL_LIMIT`. The buffer and `version` are unchanged. A grid whose image is
unplaced gets a dead (all-zero) record, and its id stays dirty until it is placed. A grid whose majorant is
unplaced is recorded without the majorant (flag b2 clear). The header `gridCount` is clamped to the table
capacity.

### 2. Allocation failure on growth: error scopes + rollback

Growth pushes `out-of-memory` and `validation` scopes around `createBuffer` and pops both at once. `update`
is synchronous, so the pool switches to the new buffer immediately (copies recorded, `version++`) and keeps the
old buffer alive (not retired) until the scopes resolve. Growths settle in order.

- **Confirmed:** the old buffer is retired (see 3). `lastError` is cleared.
- **Failed:** the pool rolls back to the old buffer and **bumps `version` again** (a new version pointing at
  the old buffer). Versions are monotonic, so a host that caches `version` always rebuilds bind groups and never
  mistakes a later buffer for one it saw. The failed buffer, and any growth chained after it, is destroyed.
  Grids that were resident in the old buffer (unchanged since) keep their ranges and are intact and readable.
  Everything else (new grids, replaces, majorants written since) is staged again from references the pool keeps
  while a growth is unconfirmed. The table is rewritten at once: restored grids are live and the rest read as
  dead until the next `update` places them, which retries the growth.

New API (minimal):

| Member | Meaning |
|---|---|
| `settled(): Promise<void>` | Resolves when every growth so far is confirmed (at once if none). Rejects with the `VDB_POOL_LIMIT` rollback error if one failed. Made on demand, so no unhandled rejections unless called. |
| `lastError: VDBError \| null` | The last growth failure, for polling in a frame loop; cleared by the next confirmed growth. |

Caveats: a host frame submitted between the failed growth and the rollback references an invalid buffer and is
dropped by the device (validation errors). Images passed to `add`/`replace` are held by reference until
`settled()` resolves, not only until the `update` that writes them. This resolves open issue 4 above.

### 3. Retired buffers live until the queue is done with them

Before, a retired buffer was destroyed at the next `update`. If the host did `update(e1)` (growth),
`update(e2)`, then `submit([e1, e2])`, `e1`'s copy read a destroyed buffer. Now a retired buffer is destroyed
only when all three hold:

1. its growth is confirmed;
2. at least two `update`s have run since the growth (`RETIRE_AFTER_UPDATES`);
3. a `queue.onSubmittedWorkDone()`, requested at that `update`, has resolved. One request covers every buffer
   that becomes ready at that update.

Contract: **submit each `update`'s encoder before the second `update` after it.** `retiredBytes` counts
retired buffers and the old buffers of unconfirmed growths. `dispose()` destroys every buffer the pool created
at once: current, retired, and both buffers of any unconfirmed growth, each exactly once. Late scope or
work-done callbacks then do nothing. The host must not submit pool work recorded before `dispose` after it.

### Changed existing tests (`pool.test.ts`)

- "grows once per update…": the old buffer is destroyed after `settled()`, two more updates and
  `completeWork()`, not at the next update.
- "VDB_POOL_LIMIT leaves the pool unchanged" became "…keeps the buffer and writes only the table". It uses two
  grids that each fit but not together, and asserts no create or copy, only table-region writes, then recovery
  by growth.
- "…at the device limit" now throws at `add`.

  buffer destroyed before `submit([e1, e2])`), no `settled`, writes swallowed. After the fix, all pass.
- Gates: `pnpm typecheck`, `pnpm build` clean; `pnpm test` 454 passed / 32 skipped; `e2e/pool-readback.spec.ts`
