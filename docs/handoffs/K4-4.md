# K4.4 handoff: resample-to-resolution bake (and the K4.5 design note)

K4.4 is implemented in `@pmndrs/vdb/tools`. K4.5 is a design note only:
[docs/design/K4-5-coarse-first.md](../design/K4-5-coarse-first.md).

## API

`packages/vdb/src/tools/nanovdb/resample.ts`, exported from `tools/index.ts`:

```ts
resampleGrid(source: Uint32Array | VdbGrid | VdbFile, options?: {
  resolution?: number;              // voxels on the longest box side, uniform voxels
  voxelSize?: number | [x, y, z];   // or a target voxel size
  dimensions?: [x, y, z];           // or exact dims: voxel size = box / dims (anisotropic)
  filter?: 'point' | 'box' | 'trilinear';   // default 'box'
  bbox?: [[x, y, z], [x, y, z]];    // world box; default = source active cell box
  cutoff?: number;                  // also require |v - background| > cutoff to stay active
  quantize?: 'fp8' | 'fpn'; tolerance?: number;
  sourceGridName?: string; gridName?: string; background?: number;
}): ResampledGrid   // BuiltGrid + { dimensions, bbox, filter, sourceVoxelSize }

resampleError(source, targetImage, { stride = 7 }): { meanAbsError, meanValue, percent, count }
```

- **Conventions.** Voxels are centred on integer index coordinates (the CPU oracle's and WGSL sampler's
  convention, and mjurczyk's `Math.round`), so voxel `i` covers `[i − ½, i + ½]`. The default box is the
  active voxels' cell box. Target voxel `j` is centred at `min + ((j + ½) / dims) · size` (his `forEachTexel`
  arithmetic), and the output Map is `world = vs · ijk + (min + vs/2)`, so the target index box is
  `[0, dims − 1]`. With `resolution`/`voxelSize` the box grows at its max side to whole voxels. With
  `dimensions` it is kept exactly and the voxels may be anisotropic.
- **Filters** are separable per-axis weight tables (both maps are axis-aligned), applied as three 1D passes over
  a gathered block of source voxels per target leaf:
  - `'point'` is the nearest voxel, his `.wvdb` bake exactly;
  - `'box'` is the area-weighted mean over the target cell;
  - `'trilinear'` is `sampleTrilinear` at the target centre.
- **Sparsity.** Only target leaves whose footprint overlaps a source leaf or active tile are visited. A target
  voxel is active iff its footprint touches an active source voxel (and passes `cutoff`). Empty leaves are
  dropped.
- **Sources.** A NanoVDB FLOAT/Fp8/FpN image is read via `treeNodes` + `leafVoxels` (CPU oracle). A parsed
  `.vdb` float grid is read via `iterLeaves`/`iterTiles`. Blocks without a leaf are constant over 8³ (tile or
  background), so they are looked up once and cached. Rotated, sheared or flipped maps throw.
- **Why `'box'` is the default.** It is the integral of the source over the target voxel. Mass, and so a fog's
  optical depth, is conserved (mass ratio 0.996–1.000 on smoke at every resolution; `'point'` drifts 0.79–1.07).
  A downsample by 2 is the exact 2×2×2 mean. Thin features fade instead of flickering with the sampling phase.
  On the pointwise error metric, though, `'point'` is equal or slightly better at ratios near 1 (his 128³ lattice
  on smoke: point 17.3%, box 18.3%; WDAS at 128: point 19.4%, box 20.4%), because the box blurs and the metric reads back with
  another trilinear blur. Both stay behind `filter`; the render A/B in the K4.5 note's settling test decides the
  default for previews (CLAUDE.md "build both, then decide").

Serializer change (needed for `dimensions`): `buildFromLeavesDetailed({ voxelSize })` accepts `[x, y, z]` and
writes a diagonal Map, GridData `voxelSize` and world bbox per axis. `BuiltGrid` gains `voxelSizeXYZ`, while
`voxelSize` stays the x component. `quantize` now carries all three components, so an anisotropic grid stays
anisotropic. Uniform builds are byte-identical to before. The core pool already reads a vec3 voxel size and
composes affines from the Map.

## Measured (smoke.vdb, gzip 9 of the `.nvdb`, error = `resampleError`)

`node scripts/measure-coarse-first.mjs smoke` (after `pnpm build`). The metric is the comparison report's:
mean |diff| over every 7th active source voxel (149,897 voxels), as a percentage of the mean, with the target
read back trilinearly. It reproduces the report's full-resolution FpN figure: **642.8 KiB, 1.21%** (report: 643
KiB, 1.2%).

| Smoke at his 128³ lattice (his box, `dimensions: [128,128,128]`), FpN | gz | error |
|---|---|---|
| point | 456.2 KiB | 17.25% |
| box | 477.2 KiB | 18.34% |
| trilinear | 475.3 KiB | 17.78% |
| report ("ours, FpN resampled to their 128³") | 474 KiB | ~18% |
| his `.wvdb` (our byte-exact re-bake) | 791.1 KiB | 17.0% |

The report's 474 KiB is reproduced to within 1% by the box/trilinear filters (point is 4% smaller). His own
LOD0 (32³) needs 14.8 KiB with header at 47.3%. Our FpN on his 32³ lattice is 12.5 KiB (box, 47.3%).

`'point'` on his lattice equals `sampleWvdbDense` (his bake) at every voxel of every emitted leaf, and no
non-zero sample of his falls outside an emitted leaf (test).

WDAS quarter cloud (24.1 M active, 16,309 lower tiles): full FpN 12,689.5 KiB gz at 0.17%. Previews (FpN, gz):
`resolution` 32 point 4.9 KiB / 36.2%, box 7.0 KiB / 35.1%; 48 point 12.6 KiB / 31.9%, box 17.1 KiB / 31.4%;
128 point 162.6 KiB / 19.4%, box 194.3 KiB / 20.4%. Box mass ratio is 1.000 at every resolution, point 0.936–1.017.
Resampling the full WDAS grid takes seconds on the CPU (not a timed claim). Full tables: the K4.5 note.

## Tests

`packages/vdb/test/tools/resample.test.ts` has 14 tests, 2 of them on smoke (skipped without
`fixtures/vdb-samples/smoke.vdb`):

- identity at the source resolution reproduces every value and the active set (point, box, trilinear; negative
  index origin);
- the world box is kept;
- downsample by 2: box is the exact 2×2×2 mean, point picks voxel `2j+1`, trilinear blends at the block centre,
  and an empty octant stays empty;
- trilinear reproduces a linear field;
- box conserves mass at ratios 0.7–4.3 with negative coordinates;
- anisotropic `dimensions`: the Map, the GridData voxel size, the world bbox, Fp8 quantize and the values agree;
- sparsity: two islands 4,000 voxels apart give two small leaf sets, and `cutoff` drops the faint one;
- the `.vdb` source path and the NanoVDB source path give byte-identical images;
- option errors are rejected;
- smoke: point equals his bake, and his 128³ with FpN gives 400–550 KiB and 15–20% error, while full-resolution
  FpN gives 1.2%.

`pnpm typecheck`, `pnpm build`, `pnpm test` green (see the commit).

A bug found on the way: the box tap search used `-1` as an "unset" sentinel for a source index, which broke box
weights at negative index coordinates. The identity test with origin `[5, -3, 2]` caught it. A WDAS measurement
taken before the fix showed a 1.04–1.24 mass ratio; the numbers here are after the fix.

## K4.5 recommendation (design note)

(a) **A preview grid first in the same multi-grid `.nvdb`, streamed with HTTP compression**:
`resampleGrid(grid, { resolution: 48, filter: 'box', quantize: 'fpn' })` named `<name>.lod48`, then the full grid.

- Smoke first paint is **11.9 KiB** of the gzip stream, against his 14.8 KiB, at 47.6% error against his 47.3%.
- The whole file is 654.4 KiB, against his 791.1 KiB, and ends at 1.2% error instead of 17%.
- (c) node stats give 10.2 KiB but 123% error. (d) range reads start at ≥ 331 KiB raw.
- The pool swaps grids with `pool.add(preview, { capacity })` → `pool.replace(id, full)`.

The settling tests are a native multi-grid read (nanovdb tools in the parity Docker image, plus EmberGen), a
browser e2e that counts compressed bytes at preview emission, and a render A/B of box vs point. The fallback is
(b), a separate preview file, which uses the same bake.
