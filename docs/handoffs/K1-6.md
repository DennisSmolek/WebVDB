# K1.6 handoff: core parity harness (the K1 regression gate)

Task K1.6 per [K1-core.md](../design/K1-core.md) §7 and §8. Files: `examples/src/harness/core-parity.{html,ts}`,
`e2e/core-parity.spec.ts`. Run: `WEBVDB_E2E_PORT=<free port> pnpm exec playwright test e2e/core-parity.spec.ts`.

## What it does

One `VDBGridPool` (`initialBytes: 4096`, `maxGrids: 2`) holds the nine primitive fixtures (ids 0-8), a throwaway
grid (id 9, removed: a dead id in the middle of the table) and `torus_fog_fp8` again (id 10) with an instance
`setTransform` (30 degree rotation, scale 0.75, translation). The buffer grew to version 6 (about 96 MiB after
doubling) and the table to 16 records; every image sits at a non-zero 32 B aligned offset. Each variant compiles
one kernel module (`queryMain` with ops read / meta / sample / world-index transforms / ray clip / world->sample /
nodeMax, plus `walkMain` for `march`) that calls only the public `vdb*` API, under a validation error scope.
Pool bind group at group 1, binding 3 (slot mode) or a host `vdbPool.value` struct (buffer mode).

## Matrix (19 variants, all pass)

| Profile | Variants |
|---|---|
| read | float, fp8, fpn, all (float+fp8+fpn), all with `isActive: false`, all in **buffer mode** |
| sample | float, fp8, fpn, all (trilinear), all nearest, all `outside: 'zero'`, all `outside: 'zero'` + nearest |
| march | float, fp8, fpn, all, all in **buffer mode**, all `outside: 'zero'` |

Every variant runs read / record / dead checks over all 10 grids, so the single-type modules also test the
negative case (grids of another type: read 0, inactive, `ok` false, sample 0, nodeMax 0, while `vdbGridType`
and the bbox still match the record). `sample`+ variants run `sample`; `sample/all`, `march/all`, `march/all/buffer`
also run the world/index transforms, world->sample and `vdbRayClip`; `march` variants run `vdbNodeMax` and the walk.

checked on its own against the twins: aligned to its dim, contains its ray midpoint, `vdbGetDim`, active flag and
`vdbNodeMax` equal `getDim` / `isActive` / `nodeMax` at the cell corner. Informational: the cell sequences were
identical to the twin on 560/560 rays on SwiftShader. Rays never have a zero component (open issue 3); every ray
`o`/`d` is f32-rounded; every 4th starts inside the box, every 7th is aimed to miss.

Runtime: **about 30 s** for the page (spec 29 s wall) on SwiftShader, below the 90 s asserted.
The page imports `@pmndrs/vdb` from source through the examples' aliases.

## Findings

1. **No GPU/twin mismatch.** Every GPU result equals its twin to the stated tolerance; read, nodeMax and walk
   cell bounds are bit-exact on SwiftShader (the spec asserts max ulp 0 there; other GPUs may differ by 1 ulp, the
   harness allows that).
2. **Sidecar vs twin/GPU: 1 ulp, by design.** `sphere_fog_fp8` and `sphere_fog_fpn` at ijk [-23, 37, -16]: the
   native sidecar says 0.99999994, the twin and GPU give 1.0. The exact decode is 0.99999996554, whose single
   rounding (a fused multiply-add in the native C++) is 0.99999994; the unfused `code * q + min` (twin and WGSL)
   rounds twice and gives 1.0. A GPU that contracts to FMA may return either. Not a bug; `sidecar-value` is
   excluded from the strict-0-ulp assertion and held to 1 ulp.
3. The probe in `scripts/lib/march-probe.mjs` is subsumed (walk, nodeMax, dead ids, `outside: 'zero'`); the script
   still works unchanged (comment added) and stays a quick local check; its logic is not shared with the page.
4. Mutation check: running the GPU walk with `leafDim 1` against the `leafDim 8` twin fails the interval checks
   on 308/480 rays; reverted.

## Fresh-eyes verification (D11), 2026-11-18

An independent agent wrote a NanoVDB reader from the pinned NanoVDB.h struct layouts alone (without reading
`tools/cpu`) and compared it with the native sidecars and the CPU twins on all nine fixtures:
- vs sidecars: 73/73 rows exact with a fused decode; the only unfused miss is sphere fp8/fpn [-23,37,-16],
  confirmed by exact arithmetic as FMA (single rounding, 0.99999994) vs two roundings (1.0).
- vs twins (5,573 coords per fixture): readValueF32 / isActive / getDim / nodeMax / nodeStats 0 mismatches,
  0 ulp; trilinear within 5.9e-8.
- Harness is not tautological: expected values come from verified twins at the exact f32 inputs sent to the
  GPU; counts match the code. **Verdict: the K1 parity gate is trustworthy.**
- Follow-ups taken: `ulps(NaN, NaN)` now fails. Open (K1.9): `readValue` returns the unrounded f64 decode on Fp
  grids while `readValueF32` matches the GPU — document or align; fixture-missing CI skips the gate.
